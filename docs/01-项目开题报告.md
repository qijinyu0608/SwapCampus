# 项目开题报告

## 项目名称
SwapCampus 校园闲置物品交易平台

## 选题背景
校内闲置物品交易长期依赖微信群和熟人转发，信息分散、信用难追溯、议价和售后缺少记录。项目拟构建一个面向校内师生的校园二手物品交易平台，以提升闲置资源流转效率。

## 项目目标
1. 实现商品发布、浏览、检索、下单和评价闭环。
2. 建立基于学号实名和信用分的可信体系。
3. 提供站内即时通讯能力。
4. 提供后台审核、举报处理和用户封禁能力。
5. 形成符合课程设计要求的完整工程文档和部署方案。

## 与闲鱼等泛二手平台的区别
- 服务范围不同：闲鱼面向社会化用户，本项目仅服务校内师生。
- 身份体系不同：闲鱼以平台账号体系为主，本项目强调校内身份认证与信用约束。
- 交易距离不同：闲鱼覆盖跨区域交易，本项目更适合校内当面交易、宿舍区和教学区附近交付。
- 商品结构不同：闲鱼品类宽泛，本项目聚焦教材、宿舍用品、数码配件、运动器材等校园高频闲置。
- 治理方式不同：闲鱼强调通用平台规则，本项目可结合校园场景做更细的审核、禁售和举报处理策略。

## 本项目的主要优势
- 用户更集中：目标用户明确，需求更稳定，便于围绕校园真实场景设计功能。
- 信任成本更低：基于校内身份、信用分、评价和操作留痕，交易风险更可控。
- 交易效率更高：商品距离近、沟通链路短，适合面交和快速流转。
- 规则更容易落地：允许类目、禁售范围、审核流程都可以按校园环境定制。
- 展示更有针对性：页面、推荐、筛选、交易信息都能围绕校园场景优化，而不是泛化设计。
- 工程价值更突出：更容易体现权限控制、审核闭环、日志记录、模块化设计等软件工程思想。

## 当前阶段说明
开题报告中的目标按“先核心闭环、后增强模块”的思路推进。当前交付版已优先落地商品流、发布、订单、消息发送、后台审核、举报处理、用户封禁与 Docker 部署；评价模块前端、完整 JWT 体系和 Socket.IO 实时推送仍作为下一阶段增强内容。

## 团队角色建议
- 组长 / 项目经理：整体推进、进度控制、答辩组织
- 前端开发：用户端与后台管理页面
- 后端开发：接口、鉴权、业务逻辑、WebSocket
- 测试与文档：测试计划、缺陷跟踪、文档维护

## 技术路线
采用 React 18 + NestJS + MySQL 8 + MinIO + Docker Compose 的全栈 TypeScript 技术方案，消息推送层为后续 Socket.IO 扩展预留接口。

## 预期成果
- 可运行的 Web 系统
- Docker Compose 一键启动环境
- 12 份课程产出文档
- 5 份管理表单文档
- 页面截图、接口验收结果与开发记录等工程证据
