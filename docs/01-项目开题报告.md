# 项目开题报告

## 项目名称
SwapCampus 校园闲置物品交易平台

## 选题背景
校内闲置物品交易长期依赖微信群和熟人转发，信息分散，信用难以追溯，交易过程也缺少稳定记录。SwapCampus 试图在校园这一明确边界内，建立一个面向师生的闲置物品交易平台，把发布、浏览、沟通、下单和治理串成一条完整链路，以提升闲置资源流转效率。

## 项目目标
本项目的目标不是做一个只停留在页面展示层面的演示系统，而是做成一个可以真正说明软件工程过程的课程设计项目。系统需要完成商品发布、浏览、检索、下单和评价等核心交易流程，同时建立基于学号实名和信用分的可信机制，并提供消息沟通、后台审核、举报处理和用户封禁等治理能力。与此同时，项目还需要形成完整的工程文档和部署方案，保证老师和同学能够直接复现。

## 与闲鱼等泛二手平台的区别
闲鱼面向更广泛的社会化用户，SwapCampus 则只服务校内师生，因此系统可以围绕校园身份、近场交易和校内治理做得更细。两者在交易距离、商品结构和治理方式上也有明显差异。前者覆盖跨区域的通用二手交易，后者更适合围绕教材、宿舍用品、数码配件和运动器材等高频校园闲置品类来设计功能。

## 本项目的主要优势
SwapCampus 的优势在于目标用户集中、交易距离更近、规则更容易落地，也更容易把权限控制、审核闭环、日志记录和模块化设计这些软件工程要点落到实际系统里。对课程设计而言，这类场景比泛化的二手平台更适合展示完整的需求分析、系统设计和验证过程。

## 当前阶段说明
项目按照“先核心闭环、后扩展能力”的节奏推进。现阶段已经落地商品流、发布、订单、评价、申诉、消息、校园服务、信用中心、后台审核、举报处理、用户封禁与 Docker 部署；完整 IM、会话治理和更高自动化覆盖率则留作后续增强。

## 团队角色建议
- 组长 / 项目经理：整体推进、进度控制、答辩组织
- 前端开发：用户端与后台管理页面
- 后端开发：接口、鉴权、业务逻辑、WebSocket
- 测试与文档：测试计划、缺陷跟踪、文档维护

## 技术路线
系统采用 React 18、NestJS、MySQL 8、MinIO 和 Docker Compose 组成的全栈 TypeScript 技术方案，并接入 SuperTokens、Meilisearch 与 Socket.IO。

## 预期成果
预期成果包括一套可运行的 Web 系统、一套可直接启动的 Docker Compose 环境、完整的课程产出文档、管理表单以及页面截图、接口验收结果和开发记录等工程证据。
