### 4.3.1 2026-06-03 顺序治理验收记录
- 验证对象：举报 `#6`，目标用户 `#40`（`user6@stu.swapcampus.cn`）
- 顺序步骤：
  - `PATCH /api/reports/6/resolve`，`nextStatus=BAN_USER`
  - 查询 `GET /api/users/moderation/list`，确认 `id=40` 的 `isBanned=true`
  - `POST /api/auth/login` 使用 `user6@stu.swapcampus.cn / SwapCampusUser2026`
  - `POST /api/reports` 使用被封禁用户再次发起举报
  - `PATCH /api/reports/6/resolve`，`nextStatus=UNBAN_USER`
  - 再次查询 `GET /api/users/moderation/list`，确认 `isBanned=false`
  - 再次执行登录
- 实际结果：
  - 封禁后 `isBanned` 真实写入数据库
  - 被封禁账号登录返回 `403`
  - 被封禁账号发起举报返回 `403`
  - 解封后登录恢复为 `201`
- 验收结论：治理闭环已在真实运行容器中验证通过

## 5. 发现的问题与处理
- 问题 1：Docker `3000` 端口被本机其他服务占用
  - 处理：后端外部端口调整为 `3001`
- 问题 2：Prisma 容器运行时缺少 OpenSSL 与正确的 engine 生成步骤
  - 处理：在 backend Dockerfile 中安装 `openssl`，并在容器内执行 `npx prisma generate`
- 问题 3：NestJS 在容器内对部分控制器/服务的注入元数据不稳定
  - 处理：为 `AuthController`、`OrdersController`、`ProductsController`、`ProductsService`、`AuthService` 添加显式 `@Inject(...)`
- 问题 4：课程设计文档初版对软件工程设计思想表达不足
  - 处理：补充架构说明、CI、IaC、事件驱动预留、容量估算与可维护性设计说明
- 问题 5：宿主机 `Node 24` 环境下前端构建受 Rollup Darwin 原生模块签名影响
  - 处理：前端构建脚本改为固定使用 `Node 20`，宿主机构建与容器构建现均可通过
- 问题 6：浏览器自动化环境在登录输入时依赖虚拟剪贴板能力
  - 处理：改为通过接口与页面静态结果双向验证管理员链路，避免把浏览器后端限制误判为系统缺陷
- 问题 7：登录接口早期仅判断账号存在，未校验密码
  - 处理：补充 `bcrypt` 密码校验，并增加旧数据密码哈希升级逻辑
- 问题 8：默认账号、数据库和文档口径曾短暂不一致
  - 处理：增加 `db:sync-default-accounts`，重建运行容器并统一默认账号说明
- 问题 9：早期文档仍将“举报处理与用户封禁”描述为待补强项
  - 处理：在 2026-06-03 顺序验收完成后，统一更新测试、用户手册和验收记录口径
- 问题 10：消息页曾按 `senderId` 奇偶数判断左右气泡，导致“我发出的消息”被显示成“对方发送”
  - 处理：改为按 `message.senderId === currentUser.id` 判断消息归属，并重新构建前端与同步容器
- 问题 11：首页活动区在分栏浏览宽度下曾出现细长竖卡堆叠，视觉上偏离闲鱼
  - 处理：重排为“窄分类栏 + 右侧活动主区 + 主卡/副卡”结构，并将 `校园服务` 从二手主流中拆为独立子模块
