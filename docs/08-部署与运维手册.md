# 部署与运维手册

## 1. 环境要求
- Docker Desktop 24+
- Node.js 20+
- npm 10+

补充说明：
- 如果仅以 Docker 方式交付给别人，必需环境只有 `Docker Desktop`
- `Node.js` 和 `npm` 主要用于本机源码开发、宿主机构建和单独调试

## 1.1 工程化资产
- `docker-compose.yml`：基础设施即代码定义
- `Makefile`：统一工程命令入口
- `.github/workflows/ci.yml`：持续集成定义
- `backend/prisma/schema.prisma`：数据库结构定义

## 2. 本地部署步骤
```bash
docker compose up -d --build
```

说明：
当前项目已完成以下验证：
- 前端宿主机构建成功
- 后端测试通过
- 当前 Docker Compose 运行中的 frontend / backend / mysql / minio 服务可访问
- Docker 首次启动会自动执行 `db-init`
- `db-init` 会完成 Prisma schema 推送与初始业务数据导入
- 后端健康接口、商品接口、订单接口、消息接口、后台审核接口可访问

补充说明：
- 前端 `package.json` 已将宿主机构建固定到 `Node 20`
- 前端 Docker 交付当前采用 `build -> dist -> nginx` 的静态发布方式
- 当前前端生产镜像已完成 Docker 重建复验
- 本机 MySQL 通过 Docker Compose 提供，无需单独安装本地服务
- 如果数据库中已存在用户数据，`db-init` 会自动跳过重复 seed，避免覆盖已有新增数据

如果 `make up` 失败，请先确认 Docker Desktop 已启动，并且本机存在可用的 Docker daemon。

建议改为：
```bash
docker compose up -d --build
```

如果需要源码依赖一起安装，再执行：
```bash
make install
```

## 3.1 首次部署与二次部署区别
- 首次部署：自动建表、自动导入初始数据、自动启动前后端
- 二次部署：保留现有 MySQL 数据卷，跳过重复 seed
- 如果要恢复到初始状态，需要删除卷后重新启动

重置命令：
```bash
docker compose down -v
docker compose up -d --build
```

## 4. 关闭服务
```bash
make down
```

等价命令：
```bash
docker compose down
```

## 5. 运维验证清单
- 访问 `http://localhost:3001/api/health`，返回 `status: ok`
- 访问 `http://localhost:3001/api/products/dashboard`，应返回商品数、用户数、待审核商品数
- 访问 `http://localhost:3001/api/products/publishing-rules`，应返回允许分类、禁售词和白名单规则
- 调用 `POST /api/messages/conversations/1` 可新增一条消息
- 调用 `GET /api/messages/conversations?userId=:id` 可查看会话列表
- 调用 `PATCH /api/admin/products/:id/status` 可执行审核通过或下架
- 调用 `POST /api/campus-services/:id/accept`、`POST /api/campus-services/:id/complete` 可验证校园服务任务流转
- 调用 `GET /api/users/:id/trust-summary`、`PATCH /api/users/:id/profile` 可验证个人中心资料与信用摘要接口
- 种子基线统计值应为：`userCount=31`、`productCount=360`、`pendingCount=33`
- 当前运行快照在本轮文档校对时为：`userCount=36`、`productCount=372`、`pendingCount=33`
- `POST /api/auth/login` 已验证管理员默认账号可登录，错误密码返回 `401`

建议补充一轮容器级检查：
- `docker compose ps` 中 `mysql`、`backend`、`frontend` 状态应为 `running`
- `db-init` 状态应为 `exited (0)`
- `docker compose logs backend --tail=50` 不应持续出现数据库连接报错
- 首页、登录页、想要页、发布页、后台页可正常打开
- `docker compose logs frontend --tail=50` 不应持续出现 `nginx` 启动错误

## 6.1 文档与运维同步原则
- 每次部署方式、端口、账号、初始化逻辑或验证命令发生变化时，同步更新本手册。
- 每轮交付前先核对本手册、`16-交付清单.md` 与真实运行态是否一致。
- 运维文档不仅说明“怎么启动”，还要保留“如何验证启动结果”和“当前版本的已知边界”。
- 文档标准与版本维护机制见 `18-文档管理与版本规范.md`。
