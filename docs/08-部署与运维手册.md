# 部署与运维手册

## 1. 文档目的

本文档用于说明当前仓库的真实本地部署方式、初始化口径、验证方法和已知边界。

当前仅覆盖课程设计交付和本机演示环境，不覆盖生产服务器、域名、HTTPS、镜像仓库和多实例发布。

## 2. 当前部署形态

- 前端：React 构建后由 `nginx` 静态托管
- 后端：NestJS 单体服务
- 数据库：MySQL 8
- 搜索：Meilisearch
- 认证：SuperTokens + PostgreSQL
- 对象存储：MinIO
- 编排方式：`docker-compose.yml`

默认运行时会启动：

- `mysql`
- `minio`
- `meilisearch`
- `supertokens-db`
- `supertokens`
- `vendure`
- `backend`
- `frontend`

可选 profile：

- `init`：一次性初始化任务 `db-init`

## 3. 环境要求

- Docker Desktop

可选本机环境：

- Node.js 20+
- npm 10+

补充说明：

- 仅按 Docker 方式运行时，不需要预先安装本机 MySQL、PostgreSQL、MinIO 或 Meilisearch。
- 本机 Node.js 主要用于执行 `npm test`、`npm run build`、Prisma 脚本和辅助脚本。

## 4. 启动方式

首次启动或清空数据后的标准步骤：

```bash
make init
make start
```

日常重启：

```bash
make start
```

说明：

- `make init` 会以 `init` profile 启动 `db-init`。
- `db-init` 当前只执行 `prisma db push` 和空库初始化检查，不自动写入演示账号、商品、订单或校园服务数据。
- 如需强制重置数据库，应显式执行 `make init-reset`，不要把重置动作放进默认初始化。
- `make start` 会启动默认运行时容器，并清理历史遗留容器 `swapcampus-supertokens-local`。
- `backend` 会等待 `mysql`、`supertokens` 等关键依赖就绪后启动。

## 4.1 API 与环境变量单独配置

推荐在仓库根目录创建 `.env`，由 Docker Compose 统一读取。

根目录 `.env.example` 已给出默认模板，至少应根据实际部署地址调整：

- `API_DOMAIN`
- `WEBSITE_DOMAIN`
- `VITE_API_BASE_URL`
- `VITE_API_DOMAIN`
- `VITE_SOCKET_URL`
- `VITE_WEBSITE_DOMAIN`

补充说明：

- `API_DOMAIN` / `WEBSITE_DOMAIN` 主要影响后端运行时、认证和媒体公开地址
- `VITE_*` 主要影响前端构建时的接口地址和站点地址
- 修改 `VITE_*` 后必须重建前端镜像，修改后端变量后需要重启相关容器
- 若要把 API 配置单独分发给后续开发人员，必须连同根目录 `.env` 一起分发

## 5. 初始化与演示数据口径

当前仓库有两种运行口径：

### 5.1 默认初始化口径

- 适用于课程演示、联调和日常开发
- 空库执行 `make init` 后只建表，不自动灌入演示数据
- 需要先注册真实账号，再逐步产生商品、订单、消息和校园服务数据

### 5.2 可选演示种子口径

如果需要快速恢复一套较完整的演示环境，可手动执行：

```bash
cd backend && npm run db:reset-and-seed-demo
```

当前可选演示种子规模为：

- 用户：10
- 商品：30
- 校园服务：18
- 商品订单：6
- 校园服务订单：4
- 举报：4

说明：

- 该脚本会清空当前业务数据后重新写入演示数据。
- 演示种子依赖已启动的 `mysql`、`supertokens`、`meilisearch` 等服务。
- 不应把“可选演示种子”误写成“默认启动结果”。

## 7. 启动后验证

### 7.1 容器状态

```bash
docker compose ps
```

预期：

- `mysql`、`minio`、`meilisearch`、`supertokens-db`、`supertokens`、`vendure`、`backend`、`frontend` 为 `running`
- 若刚执行过初始化，`db-init` 应为 `exited (0)`

### 7.2 健康检查

```bash
curl http://127.0.0.1:3001/api/health
```

预期返回：

```json
{"status":"ok"}
```

### 7.3 后端日志

```bash
docker compose logs backend --tail=50
```

预期：

- 不应持续出现数据库连接失败
- 不应持续出现 Prisma 初始化失败
- 不应持续出现 SuperTokens 连接失败

### 7.4 前端与核心接口验证

建议至少验证：

- 首页可打开
- 登录页可注册或登录
- 发布页可上传图片并提交商品
- 消息页可读取会话
- 校园服务页可读取服务列表
- 后台页可打开并读取治理数据

也可补充以下接口检查：

- `GET /api/products/dashboard`
- `GET /api/products/publishing-rules`
- `GET /api/products/home-recommendations`
- `GET /api/favorites`
- `GET /api/credit-center/summary`
- `GET /api/admin/overview`

## 8. 重置与维护命令

清空容器和数据卷：

```bash
docker compose down -v
```

重建初始化：

```bash
make init
make start
```

强制重置数据库：

```bash
make init-reset
make start
```

常用命令：

```bash
make install
make up
make start
make init-reset
make restart-auth
make restart-backend
make status
make health
make down
make logs
make backend-test
make frontend-build
```

## 9. 当前已知边界

- 消息模块已接入 Socket.IO 房间推送，但仍缺少已读回执、在线状态和断线补偿
- 登录用户收藏已经走后端 `Favorite` 表，游客模式仍保留本地临时想要
- 认证主链路已统一到 `SuperTokens session`，但更完整的 refresh / rotation 治理仍可继续增强
- MinIO、媒体上传、商品多图和消息附件已经落地，但生产化媒体治理仍可继续补强
- 自动化验证当前以后端 Jest 和前端 build 为主，前端交互级测试仍不充分

## 10. 对外分发建议

- 直接交付整个 `SwapCampus` 仓库目录
- 重点附带 `README.md`、本手册、截图证据
- 对方若需要独立修改 API 地址、认证密钥或 LLM 密钥，必须额外分发根目录 `.env`
- 若对方需要本机脚本运行能力，可同时分发 `backend/.env` 与 `vendure/.env`
- 若对方只做课程演示，优先推荐 Docker 启动，不建议先拆本机源码环境
