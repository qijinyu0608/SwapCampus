# 部署与运维手册

## 1. 文档目的

本文档说明当前仓库的本地部署方式、初始化口径、验证方法和已知边界。内容只覆盖课程设计交付和本机演示环境，不涉及生产服务器、域名、HTTPS、镜像仓库或多实例发布。

## 2. 当前部署形态

- 前端：React 构建后由 `nginx` 静态托管
- 后端：NestJS 业务主服务 `backend`
- 异步工作进程：`search-indexer`、`commerce-sync`
- 数据库：MySQL 8
- 搜索：Meilisearch
- 认证：SuperTokens + PostgreSQL
- 对象存储：MinIO
- 编排方式：`docker-compose.yml`

默认运行时会启动 `mysql`、`minio`、`meilisearch`、`supertokens-db`、`supertokens`、`vendure`、`backend`、`search-indexer`、`commerce-sync` 和 `frontend`。可选的 `init` profile 用于执行一次性初始化任务 `db-init`。

## 3. 环境要求

- Docker Desktop

可选本机环境：

- Node.js 20+
- npm 10+

仅按 Docker 方式运行时，不需要预先安装本机 MySQL、PostgreSQL、MinIO 或 Meilisearch。本机 Node.js 主要用于执行 `npm test`、`npm run build`、Prisma 脚本和辅助脚本。

## 4. 启动方式

首次启动或清空数据后的标准步骤：

```bash
make init
make start
```

日常重启：

```bash
make start
```

说明：

- `make init` 会以 `init` profile 启动 `db-init`。
- `db-init` 当前只执行 `prisma db push` 和空库初始化检查，不自动写入演示账号、商品、订单或校园服务数据。
- 如需强制重置数据库，应显式执行 `make init-reset`，不要把重置动作放进默认初始化。
- `make start` 会启动默认运行时容器，并清理历史遗留容器 `swapcampus-supertokens-local`。
- `backend` 会等待 `mysql`、`supertokens` 等关键依赖就绪后启动。
- 默认情况下，搜索索引消费由 `search-indexer` 承担，Vendure 异步同步由 `commerce-sync` 承担，`backend` 中对应 worker 开关默认关闭。

## 4.1 API 与环境变量单独配置

推荐在仓库根目录创建 `.env`，由 Docker Compose 统一读取。

根目录 `.env.example` 已给出默认模板，至少应根据实际部署地址调整：

- `API_DOMAIN`
- `WEBSITE_DOMAIN`
- `VITE_API_BASE_URL`
- `VITE_API_DOMAIN`
- `VITE_SOCKET_URL`
- `VITE_WEBSITE_DOMAIN`

`API_DOMAIN` 和 `WEBSITE_DOMAIN` 主要影响后端运行时、认证和媒体公开地址，`VITE_*` 则影响前端构建时的接口地址和站点地址。修改 `VITE_*` 后必须重建前端镜像，修改后端变量后需要重启相关容器。若后续需要单独分发 API 配置，也应连同根目录 `.env` 一并交付。

## 5. 初始化与演示数据口径

当前仓库存在两种运行口径：

### 5.1 默认初始化口径

默认初始化适用于课程演示、联调和日常开发。空库执行 `make init` 后只建表，不自动灌入演示数据，需要先注册真实账号，再逐步生成商品、订单、消息和校园服务数据。

### 5.2 可选演示种子口径

如果需要快速恢复一套较完整的演示环境，可手动执行：

```bash
cd backend && npm run db:reset-and-seed-demo
```

当前可选演示种子规模为：

- 用户：10
- 商品：30
- 校园服务：18
- 商品订单：6
- 校园服务订单：4
- 举报：4

该脚本会清空当前业务数据后重新写入演示数据，依赖已启动的 `mysql`、`supertokens`、`meilisearch` 等服务。不应把这套演示种子误写成默认启动结果。

## 7. 启动后验证

### 7.1 容器状态

```bash
docker compose ps
```

预期：

- `mysql`、`minio`、`meilisearch`、`supertokens-db`、`supertokens`、`vendure`、`backend`、`search-indexer`、`commerce-sync`、`frontend` 为 `running`
- 若刚执行过初始化，`db-init` 应为 `exited (0)`

### 7.2 健康检查

```bash
curl http://127.0.0.1:3001/api/health
```

预期返回：

```json
{"status":"ok"}
```

### 7.3 后端日志

```bash
docker compose logs backend --tail=50
```

预期：

- 不应持续出现数据库连接失败
- 不应持续出现 Prisma 初始化失败
- 不应持续出现 SuperTokens 连接失败

如需检查异步消费链路，建议再补看：

```bash
docker compose logs search-indexer --tail=50
docker compose logs commerce-sync --tail=50
```

预期：

- `search-indexer` 能正常启动并周期性轮询 `search.index`
- `commerce-sync` 能正常启动并周期性轮询 `commerce.sync`
- 不应持续出现 Meilisearch 或 Vendure 连接失败

### 7.4 前端与核心接口验证

建议至少验证：

- 首页可打开
- 登录页可注册或登录
- 发布页可上传图片并提交商品
- 消息页可读取会话
- 校园服务页可读取服务列表
- 后台页可打开并读取治理数据

也可补充以下接口检查：

- `GET /api/products/dashboard`
- `GET /api/products/publishing-rules`
- `GET /api/products/home-recommendations`
- `GET /api/favorites`
- `GET /api/credit-center/summary`
- `GET /api/admin/overview`

## 8. 重置与维护命令

清空容器和数据卷：

```bash
docker compose down -v
```

重建初始化：

```bash
make init
make start
```

强制重置数据库：

```bash
make init-reset
make start
```

常用命令：

```bash
make install
make up
make start
make init-reset
make restart-auth
make restart-backend
make restart-search-indexer
make restart-commerce-sync
make backfill-search-outbox
make status
make health
make down
make logs
make backend-test
make frontend-build
make docs-docx
```

## 8.1 GitHub Actions 校验与文档产物

仓库中的 `.github/workflows/ci.yml` 会在 `push`、`pull_request` 和手动触发时执行三类任务：

- 后端 `npm test`
- 前端 `npm run build`
- 课程设计文档 `python3 scripts/generate_course_docx.py`

其中课程设计文档 job 会安装 `requirements-docs.txt` 中定义的 Python 依赖，并把 `docs/generated-docx/` 上传为 `course-docx` artifact。需要在本地复现该流程时，先创建虚拟环境并安装依赖，再执行 `make docs-docx`：

```bash
python3 -m pip install --target .docs-py -r requirements-docs.txt
make docs-docx
```

## 9. 当前已知边界

消息模块虽然已经接入 Socket.IO 房间推送，但仍缺少已读回执、在线状态和断线补偿。登录用户收藏已经走后端 `Favorite` 表，游客模式仍保留本地临时想要。认证主链路已统一到 `SuperTokens session`，但 refresh 和 rotation 等更完整的会话治理还可以继续增强。媒体上传和商品多图已经落地，不过生产化媒体治理仍有提升空间。自动化验证目前以后端 Jest 和前端构建为主，前端交互级测试还不够充分。事件驱动部分已经形成独立 worker，但当前监控、告警和人工补偿能力仍然偏轻量。

## 10. 对外分发建议

建议直接交付整个 `SwapCampus` 仓库目录，并附带 `README.md`、本手册和截图证据。若对方需要独立修改 API 地址、认证密钥或 LLM 密钥，应同时分发根目录 `.env`；若还需要本机脚本运行能力，可一并提供 `backend/.env` 与 `vendure/.env`。如果只是用于课程演示，优先推荐 Docker 启动，不建议先拆本机源码环境。

## 11. 文档同步要求

启动方式、端口、初始化口径、演示数据脚本或关键依赖发生变化时，必须同步更新本手册。若 `README.md`、`16-交付清单.md` 与本手册不一致，应以当前源码为准，并在同一轮内完成修正。
