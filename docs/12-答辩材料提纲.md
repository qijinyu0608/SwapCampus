# 答辩材料提纲

## 1. 背景

答辩开场应先交代问题背景：当前校园闲置交易长期分散在微信群、朋友圈和熟人转发中，信息不集中、信用难判断、交易记录也不完整。SwapCampus 的出发点，就是把交易、沟通、治理和信用放到同一系统中处理。

## 2. 系统定位

系统定位要强调三点：第一，服务对象明确限定为校内师生；第二，目标不是只展示页面，而是完成一个具备真实业务闭环的课程设计系统；第三，项目需要在功能之外提供可复现部署、可验证测试和可追溯文档。

## 3. 核心功能

核心功能介绍建议按用户主链路展开，依次说明注册登录、商品浏览与发布、收藏与推荐、订单创建、评价与申诉、消息沟通、校园服务、信用中心和后台治理。这样组织更贴近老师现场观看系统的顺序，也更容易把“为什么要这样设计”讲清楚。

## 4. 技术与部署

技术部分重点说明当前采用 React、NestJS、Prisma、MySQL、MinIO、SuperTokens、Meilisearch 和 Socket.IO 组成的实现方案，并强调项目可通过 Docker Compose 快速启动，能够在统一环境中完成复现和验收。

## 5. 数据口径

数据口径部分必须讲清楚：默认初始化是空库建表，不自动导入演示数据；如需答辩演示，可以通过脚本重建演示种子；运行中的实际统计会持续变化，因此文档里不再把演示种子误写成默认运行态。

## 6. 展望

最后的展望部分可收束为三个方向：继续完善 IM 能力、进一步细化治理策略、提高自动化测试覆盖率。这样既能体现项目仍有演进空间，也能和当前“已完成什么、尚缺什么”的边界保持一致。
