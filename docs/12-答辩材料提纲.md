# 答辩材料提纲

## 1. 项目背景与问题定义
- 校园二手交易长期依赖微信群，信息碎片化、信用弱、交易记录不可追溯
- SwapCampus 的目标是把“发布-沟通-下单-审核”放进一个统一系统
## 2. 用户角色与业务流程
- 角色：游客、普通用户、管理员
- 核心流程：注册登录 -> 发布商品 -> 浏览商品 -> 站内沟通 -> 创建订单 -> 后台审核
## 3. 技术选型与系统架构
- 前端：React 18 + TypeScript + Vite + Ant Design
- 后端：NestJS + TypeScript + Prisma
- 数据库：MySQL 8
- 部署：Docker Compose
- 说明为何统一选择 TypeScript 和容器化
## 4. 核心功能演示
- 首页：真实商品流与统计数据
- 登录：真实注册落库与账号登录
- 发布：提交商品进入待审核
- 消息：查看会话并发送消息
- 个人中心：查看用户资料与最新订单
- 后台：审核通过/下架待审核商品，处理举报并演示封禁/解封
## 5. 数据库与部署方案
- 说明核心表：`users`、`products`、`orders`、`conversations`、`messages`
- 演示 Docker Compose 启动的四个服务
- 说明“课程要求不少于 200 条商品”与当前 360 条种子数据之间的关系，以及为什么要区分种子基线和运行快照
## 6. 测试结果与工程规范
- 后端 `npm test` 通过
- 前端 Docker 构建通过
- 验证消息发送接口与后台审核接口真实生效
- 文档与代码同步维护，形成开发记录
## 7. 总结与展望
- 当前版本已达到课程设计可交付标准
- 后续可继续补 Socket.IO 实时推送、完整 JWT 鉴权、申诉与更细粒度治理策略，以及更多自动化测试
