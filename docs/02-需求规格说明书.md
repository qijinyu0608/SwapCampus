# 需求规格说明书

## 1. 引言

SwapCampus 面向校内师生，提供闲置商品交易、校园服务、站内沟通和后台治理能力。

## 2. 用户角色

- 游客：浏览首页、商品详情、公开用户主页
- 普通用户：注册、登录、发布、收藏、下单、消息、校园服务、信用中心
- 管理员：审核、举报、申诉、用户治理、审计查看

## 3. 核心需求

### 3.1 用户体系

- 支持学号或邮箱注册登录
- 支持实名补充信息与实名状态展示
- 支持账号封禁拦截
- 支持个人资料维护

### 3.2 商品能力

- 商品列表、搜索、详情
- 商品多图上传
- 商品发布规则读取
- 商品发布与审核
- 商品收藏与推荐联动

### 3.3 交易能力

- 线下面交订单创建
- 订单状态流转
- 订单评价
- 订单申诉
- 订单快照查看

### 3.4 消息能力

- 会话列表
- 消息明细
- 文本与附件发送
- Socket.IO 演示级实时推送

### 3.5 校园服务能力

- 支持 `REQUEST / OFFER` 两种发布意图
- 支持校园服务发布、筛选、收藏、接单、完成
- 支持校园服务订单与消息联动

### 3.6 信用与成长能力

- 商品、校园服务、用户页展示信用摘要
- 信用中心支持签到、任务、账本和奖励兑换

### 3.7 后台治理能力

- 商品审核
- 举报处理
- 用户封禁 / 解封
- 实名审核
- 订单申诉处理
- 审计日志

## 4. 非功能需求

- Docker Compose 可复现部署
- 文档与代码同仓维护
- 后端测试与前端构建纳入 CI
- 页面保持可演示、可复现、可追溯

## 5. 数据口径要求

- 默认初始化为“空库建表”
- 可选演示种子为“手动重建的数据集”
- 动态运行数据不得写成固定常量

## 6. 当前实现边界

- 消息模块仍缺少已读回执、在线状态、断线补偿
- 会话治理仍可继续补 refresh / rotation 等增强能力
- 前端交互级自动化测试仍不充分
