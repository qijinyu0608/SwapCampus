# 需求规格说明书

## 1. 引言
本系统服务于本校师生，支持二手物品发布、检索、交易和评价，目标是替代散点化的微信群交易模式。

## 1.1 编写目的
- 明确 SwapCampus 的业务边界、核心流程与可交付范围。
- 为概要设计、详细设计、数据库设计、测试与验收提供统一依据。
- 为课程设计中期检查、最终答辩与文档归档提供可追溯的需求基线。

## 1.2 业务目标
- 建立面向校内师生的二手交易平台，提升闲置物品流转效率。
- 通过学号实名、信用分、订单留痕与举报审核降低交易风险。
- 以低学习成本完成“浏览、想要、沟通、下单、面交、确认”的核心闭环。

## 1.3 与泛二手平台的定位差异
- 本系统不是面向社会化用户的综合二手平台，而是面向校内师生的校园闲置交易平台。
- 本系统重点解决“同校、近场、可信、可管理”的交易问题，不追求覆盖闲鱼式的大而全品类。
- 本系统商品范围更聚焦校园高频闲置，如教材、宿舍用品、小电器、数码配件、运动器材等。
- 本系统更强调校内身份认证、信用分、审核、举报和操作留痕等治理能力。
- 本系统默认以校内面交、小范围流转为主要交易方式，减少跨地区物流与陌生交易风险。

## 1.4 相对闲鱼的产品优势
- 用户更精准：用户群体集中在本校，需求更明确，便于做针对性功能设计。
- 信任基础更强：基于校内身份、评价与信用信息，降低交易双方的信息不对称。
- 交易路径更短：同校交易可减少沟通成本、运输成本和等待时间。
- 管理约束更清晰：平台可按校园场景设置允许类目、禁售规则和审核标准。
- 推荐更有效：推荐结果可结合校内热门品类、宿舍生活、课程周期等场景特征优化。
- 产品更适合课程设计：既有完整交易流程，也能体现权限、审核、日志、模块化等工程思想。

## 2. 用户角色
- 游客：浏览首页、搜索商品、查看商品详情
- 普通用户：浏览商品、收藏、发布商品、下单、聊天、评价
- 管理员：审核商品、处理举报、封禁用户、查看数据看板

## 3. 功能需求
### 3.1 用户体系
- 学号、姓名、邮箱、手机号维护
- 实名认证信息录入与审核状态展示
- 浏览器本地登录态维护
- 默认信用分 60 分
- 管理员账号支持进入后台审核
- 支持个人资料编辑、学院与手机号补充维护
- 支持个人信用摘要展示，包括信用分、实名状态、进行中订单和成交记录

### 3.1.1 用户体系验收点
- 学生可通过学号或邮箱登录。
- 游客进入系统后只能浏览，不可发布、沟通和下单。
- 普通用户同时具备买家与卖家能力，角色不互斥。
- 管理员进入后台后可查看待审核商品、举报与操作留痕。

### 3.2 商品发布与管理
- 支持标题、分类、成色、价格、标签、描述、多图上传
- 商品状态支持待审核、在售、已售、已下架
- 发布后进入审核流，再决定是否进入首页展示
- 支持同校交易语境下的标题、标签、描述表达
- 提供发布规则读取能力，前端展示允许分类、禁售词、宿舍电器白名单和审核流程提示
- 对禁售词、违规宿舍电器、超规格充电宝等内容进行自动拦截
- 管理员可对待审核商品执行恢复展示或下架处理

### 3.3 商品检索
- 首页商品流
- 分类展示
- 价格、成色、状态展示
- 按发布时间排序
- 支持按关键词、价格、成色、交易方式筛选
- 支持基于“猜你喜欢 / 分类标签 / 热门词”的快速浏览
- 支持根据用户行为动态调整推荐结果，至少考虑浏览、想要、联系、下单等信号
- 首页默认态需保持“先活动区、后商品流、筛选折叠”的轻量结构

### 3.3.1 想要与收藏
- 用户可在首页卡片和商品详情页执行“想要/取消想要”
- 想要列表需集中展示已收藏商品，并支持回到详情页继续沟通或取消收藏
- 想要行为需要作为推荐输入信号留痕
- 游客可进入想要页，但不应拥有完整交易写操作能力

### 3.4 交易流程
- 普通用户下单
- 买卖双方在关联会话中约定线下面交时间地点
- 线下当面验货和交易
- 完成后进行评价
- 支持交易前取消订单
- 订单生成后同步产生站内沟通入口
- 支持常约地点、验货、议价等校园场景信息
- 订单需要支持分页查询，便于个人中心展示最近订单与历史订单
- 订单状态至少包含 `PENDING`、`IN_PROGRESS`、`WAITING_REVIEW`、`COMPLETED`、`CANCELED`
- 订单不包含线上付款、发货、物流和收货流程

### 3.5 站内通讯
- 会话列表
- 文本消息发送
- 图片消息字段预留
- 会话按最近活跃排序
- 会话与商品、订单建立关联
- 会话需兼容校园服务任务上下文
- 前端消息页应正确区分本人消息与对方消息
- 当前版本允许使用 HTTP 落库配合 Socket.IO 房间推送实现演示级实时更新

### 3.6 后台管理
- 商品审核
- 举报数量展示
- 数据统计展示
- 操作留痕记录审核动作
- 举报支持已处理、驳回、下架商品等状态流转
- 支持基于举报直接封禁用户、解除封禁用户
- 用户封禁后应拦截登录和关键写操作，并下架其待审/在售商品

### 3.6.1 校园服务子模块
- 校园跑腿、代办代取、校内拼单、临时帮忙单独成模块
- 支持任务发布、接单、完成与消息联动
- 支持按地点、任务标题、状态筛选
- 支持北林校内真实地点作为任务起止点
- 任务状态至少覆盖 `OPEN`、`MATCHED`、`DONE`、`CANCELED`
- 接单后系统应自动建立关联会话，供双方继续确认细节

### 3.6.2 求购与借用扩展位
- 需求规格中保留求购与借用能力扩展位
- 当前版本先通过分类、描述模板与校园服务子模块承接部分需求表达
- 后续可扩展为独立的“求购”与“借用”发布流

### 3.7 推荐与信用
- 首页推荐结果综合浏览偏好、收藏偏好、分类命中与热度信息生成。
- 用户信用分至少体现实名状态、成交记录、回复率、评分等维度。
- 商品详情页与个人页需要展示信用相关信息，帮助用户快速判断交易风险。
- 推荐结果需要使用行为数据留痕支撑，包括浏览、收藏、联系、下单等事件。
- 推荐理由需要尽量可解释，至少可表现为“同类”“常看”“想要过”“信用好”等轻量标签
- 商品详情页需要展示举报数、想要数、浏览热度等交易参考信号

### 3.8 文档与追溯要求
- 文档必须覆盖需求、设计、数据库、测试、部署、验收、总结和过程记录。
- 文档必须与当前实现同步维护，不允许开发结束后集中补写。
- 需求、实现、测试、验收之间必须建立可追溯关系。
- 对动态变化的数据，应区分可复现种子基线和运行快照两种口径。

## 4. 关键业务流程
### 4.1 商品发布流程
1. 普通用户登录。
2. 进入发布页填写标题、分类、价格、成色、标签、描述。
3. 系统保存商品并标记为 `PENDING`。
4. 管理员在后台审核，通过后商品进入 `ON_SALE`。

### 4.2 商品购买流程
1. 用户在首页或详情页浏览商品。
2. 通过想要、聊天或直接下单建立交易联系。
3. 系统创建订单并生成关联会话。
4. 商品从首页交易流中临时隐藏，避免多人重复下单。
5. 双方确认线下面交时间地点后，订单进入待面交状态。
6. 如无法继续交易，任一参与方可取消订单，商品恢复可交易。
7. 当面验货和线下交易完成后，订单进入待评价状态。
8. 用户提交评价后，订单完成，商品标记为已售。

### 4.3 举报处理流程
1. 普通用户在商品详情页发起举报。
2. 举报记录进入后台待处理列表。
3. 管理员选择驳回、已处理、下架商品、封禁用户或解除封禁。
4. 系统记录处理结果、操作日志与目标账号状态变更。

## 5. 非功能需求
- 单元测试覆盖率目标不低于 60%，当前版本先保证核心接口与主要链路可验证
- Docker Compose 一键启动
- 商品种子数据不少于 200 条
- 页面默认态强调简洁，关键信息优先，长说明后置折叠
- 前后端代码均使用 TypeScript
- 文档采用 Markdown 扁平目录管理
- 需要保留未来扩展 Socket.IO、JWT、对象存储多图上传的结构余地

## 6. 数据与接口约束
- 商品核心字段：标题、分类、成色、价格、标签、描述、状态、卖家信息。
- 订单核心字段：商品、买家、卖家、约定地点、备注、状态。
- 会话核心字段：商品、订单、发送人、消息内容、创建时间。
- 举报核心字段：举报人、商品或用户目标、原因、处理状态、处理备注。
- 校园服务任务核心字段：标题、分类、酬谢金额、起点、终点、截止时间、预计耗时、发布者、接单人、状态。
- 用户行为核心字段：用户、商品、行为类型、发生时间。
- 用户资料核心字段：姓名、邮箱、真实姓名、学院、手机号、实名状态。
- 推荐接口至少需要返回推荐商品摘要、推荐理由和卖家可信度摘要。

## 7. 当前实现边界
- 当前版本已完成：首页、登录、发布、消息、个人中心、后台页面的真实业务演示
- 当前版本已完成：用户注册、商品发布、想要收藏、订单创建、线下面交约定、订单取消、成交确认、评价提交、消息发送、校园服务任务流转、商品审核通过/下架、举报处理、用户封禁与解除封禁、资料编辑与信用摘要展示
- 当前版本未完成：完整 JWT 权限链路、已读回执/在线状态/断线补偿等完整 IM 能力、细粒度申诉与处罚策略、收藏后端持久化独立模型

## 8. 验收重点
- 是否具备游客、普通用户、管理员三类角色的基本权限差异。
- 是否能够完成发布、浏览、沟通、下单、审核的主链路。
- 是否通过真实数据库与容器化方式实现可复现部署。
- 页面默认态是否做到“先简洁、后展开”，避免课程作业式平铺说明。
