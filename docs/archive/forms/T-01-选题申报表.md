## 3 选择本题的理由（≥ 200 字）

本小组选择该题目的理由如下：
- 场景真实：校园内教材、台灯、风扇、收纳架、球拍、键盘、移动电源等物品流转需求明确，容易调研，也便于演示。
- 用户明确：目标用户集中在校内师生，需求边界清晰，便于聚焦核心功能。
- 业务完整：除商品发布、浏览、搜索、沟通、下单外，还能覆盖审核、举报、评价、信用等完整链路。
- 工程价值强：适合体现角色权限、状态流转、模块划分、日志留痕、规则约束等软件工程内容。
- 治理特点突出：不只考虑“能不能交易”，还考虑“能不能规范交易、能不能追溯责任、能不能持续管理”。
- 产品空间充足：可引入游客登录、实名认证、信用分、推荐排序、商品曝光、管理员审核等成熟产品机制。
- 对比优势明确：相较于闲鱼这类泛二手平台，本项目更聚焦校园内部，身份更真实，交易半径更短，治理规则更容易落地。
- 校园信任更强：基于校内身份、信用分、举报处理和审核记录，可降低陌生人交易的不确定性。
- 校园特色明显：可以围绕校内常见类目设计品类规则，避免做成泛电商模板。
- 数据易落地：商品标题、价格、图片、成色、交易状态都较容易填充为接近真实的数据。
- 展示效果好：首页商品流、详情页、消息页、后台页都具备较强的答辩展示价值。
- 技术路线稳定：前后端分层清晰，适合用模块化方式开发与协作。
- 扩展性较好：后续可平滑增加推荐、收藏、信用规则、封禁策略、数据统计等能力。
- 风险可控：核心交易闭环明确，可先完成基础版本，再逐步补强治理与体验能力。
- 综合来看，本题兼顾真实需求、工程难度、展示效果和课程要求，适合作为本组课程设计项目。

## 5 已识别的主要风险（≥ 3 条）

1. 风险：商品范围界定不清。
   影响：平台定位模糊，业务边界不合理。
   应对计划：先定义允许类目与禁止类目，发布时增加分类约束与审核兜底。

2. 风险：信用分、推荐、权限设计过重。
   影响：开发周期拉长，核心功能延期。
   应对计划：先完成交易闭环，再做轻量规则，优先实现可解释版本。

3. 风险：页面内容空泛、数据失真。
   影响：产品成熟度不足，答辩说服力偏弱。
   应对计划：补充校园真实语境的商品数据，控制图片体积，保证信息完整。

4. 风险：审核、举报、下架流程缺少记录。
   影响：系统治理能力弱，责任难追溯。
   应对计划：为关键操作增加处理状态、操作人、时间戳和日志记录。

5. 风险：多人协作时接口和职责边界不清。
   影响：联调效率下降，返工增加。
   应对计划：按模块拆分任务，提前统一接口与字段约定。

6. 风险：界面表现过于原型化。
   影响：产品可信度和完成度受影响。
   应对计划：控制圆角与装饰，提升信息密度，强化价格、成色、信用、热度等交易信号。
