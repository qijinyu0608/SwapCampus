# 文档归档说明

`docs/archive/` 用于存放不再作为“当前基线”直接维护的历史材料，避免它们继续和现行主文档、`agent/` 规范混在同一入口里。

## 1. 归档原则

- 已完成整改、仅保留追溯价值的专题文档，移入归档。
- 阶段性过程材料、课程表单、历史计划稿，移入归档。
- 仍用于描述当前系统现状、后续设计基线或课程主交付内容的文档，保留在 `docs/` 根目录。

## 2. 当前归档结构

- `process/`
  - 阶段性过程材料，例如中期检查报告
- `technical/`
  - 已完成整改或只保留历史问题背景的专题技术文档
- `forms/`
  - 课程表单、申报表、互评表、周报等模板化材料
- `planning/`
  - 历史规划稿、superpowers 生成过程材料等

## 3. 使用口径

- 需要看“当前系统是什么”，优先读 `docs/00-文档目录.md` 中的现行文档和 `agent/` 规范。
- 需要看“为什么当时这样改”或“课程过程材料”，再进入 `docs/archive/`。
- 若归档文档与源码、`README.md` 或 `agent/` 表述不一致，以当前实现和现行文档为准。
