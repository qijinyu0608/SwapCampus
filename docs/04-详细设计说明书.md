# 详细设计说明书

## 1. 认证模块

关键接口：

- `POST /api/auth/register`
- `POST /api/auth/login`
- `POST /api/auth/logout`
- `GET /api/auth/me`

当前实现：

认证模块基于 SuperTokens 建立会话，注册时支持头像与学生证图片上传，业务用户表与认证用户保持同步。

## 2. 商品模块

关键接口：

- `GET /api/products`
- `GET /api/products/home-recommendations`
- `GET /api/products/publishing-rules`
- `GET /api/products/dashboard`
- `GET /api/products/:id`
- `POST /api/products`
- `POST /api/products/:id/contact`

当前实现：

商品发布需要至少一张图片，图片先上传到 MinIO，再把地址写入 `ProductImage`。发布流程先过本地规则，再进入内容审核；通过后进入 `ON_SALE` 状态。商品事务提交时还会同时写入 `search.index` 与 `commerce.sync` 主题事件，为后续搜索收敛和 Vendure 异步同步提供入口。

## 3. 收藏模块

关键接口：

- `GET /api/favorites`
- `POST /api/favorites/:productId`
- `DELETE /api/favorites/:productId`

当前实现：

登录用户的收藏会落库，游客只保留本地临时想要，收藏状态也会反馈到推荐和行为统计中。

## 4. 订单模块

关键接口：

- `GET /api/orders`
- `GET /api/orders/:id`
- `POST /api/orders`
- `PATCH /api/orders/:id/meetup`
- `PATCH /api/orders/:id/cancel`
- `PATCH /api/orders/:id/complete`
- `POST /api/orders/:id/reviews`
- `POST /api/orders/:id/appeals`

当前实现：

创建订单后，系统会自动生成或绑定会话，并保留商品快照。订单创建、取消、完成都会同步回写本地 `commerceSyncStatus`，并写入对应 Outbox 事件；订单完成后可继续评价，也支持申诉流程。

## 5. 消息模块

关键接口：

- `GET /api/messages/conversations`
- `POST /api/messages/conversations`
- `GET /api/messages/conversations/:id`
- `POST /api/messages/conversations/:id`
- `POST /api/media/messages`

当前实现：

消息读写由 REST 接口负责，`message:new` 房间推送由 Socket.IO 负责，握手和会话订阅都会做认证校验。

## 6. 校园服务模块

关键接口：

- `GET /api/campus-services`
- `GET /api/campus-services/:id`
- `POST /api/campus-services`
- `PATCH /api/campus-services/:id`
- `POST /api/campus-services/:id/orders`
- `POST /api/campus-services/:id/pause`
- `POST /api/campus-services/:id/reopen`
- `POST /api/campus-services/:id/end`
- `GET /api/campus-service-orders`
- `GET /api/campus-service-orders/:id`
- `POST /api/campus-service-orders/:id/confirm`
- `POST /api/campus-service-orders/:id/reject`
- `POST /api/campus-service-orders/:id/complete`
- `POST /api/campus-service-orders/:id/confirm-complete`
- `POST /api/campus-service-orders/:id/cancel`
- `GET /api/campus-service-favorites`
- `POST /api/campus-service-favorites/:listingId`
- `DELETE /api/campus-service-favorites/:listingId`

当前实现：

校园服务同时支持 `REQUEST / OFFER`，也支持发布、接单、收藏、完成和消息联动。

## 7. 用户与信用模块

关键接口：

- `GET /api/users/:id/trust-summary`
- `GET /api/users/:id/reviews`
- `GET /api/users/:id/profile`
- `GET /api/users/me/history`
- `GET /api/users/me/following`
- `POST /api/users/:id/follow`
- `DELETE /api/users/:id/follow`
- `PATCH /api/users/:id/profile`
- `PATCH /api/users/:id/ban-status`
- `PATCH /api/users/:id/verification-status`

信用中心接口：

- `GET /api/credit-center/summary`
- `POST /api/credit-center/check-in`
- `GET /api/credit-center/missions`
- `POST /api/credit-center/missions/:missionCode/claim`
- `GET /api/credit-center/ledger`
- `GET /api/credit-center/rewards`
- `POST /api/credit-center/rewards/:rewardCode/redeem`

当前实现：

用户资料编辑、封禁解封和实名认证结果变更，除了更新主业务字段外，还会按需发布卖家搜索相关事件，用于重建卖家商品的搜索可见性。信用中心围绕资产、任务、账本和兑换建立独立数据模型，不依赖前端本地缓存维持状态。

关键接口：

- `GET /api/admin/products/:id/preview`
- `PATCH /api/admin/products/:id/status`
- `GET /api/admin/orders`
- `PATCH /api/admin/orders/:id/status`
- `GET /api/admin/order-appeals`
- `PATCH /api/admin/order-appeals/:id/resolve`
- `GET /api/admin/campus-services`
- `GET /api/admin/campus-services/:id/preview`
- `PATCH /api/admin/campus-services/:id/status`
- `GET /api/reports`
- `GET /api/reports/logs`
- `POST /api/reports`
- `PATCH /api/reports/:id/resolve`

## 9. 媒体模块

关键接口：

- `POST /api/media/images`
- `POST /api/media/messages`
- `GET /api/media/files`

当前实现：

商品图片、头像、学生证、校园服务图片和消息附件都统一走媒体模块，MinIO bucket 会在启动时自动检查和创建。

## 10. 事件外发与异步处理

当前实现：

系统已新增 `outbox` 基础设施，统一负责把搜索索引同步和 Vendure 同步这两类副作用从主事务中拆出。`OutboxEvent` 记录主题、事件类型、聚合对象、载荷、重试次数和处理状态；`search-indexer` 负责消费 `search.index` 主题并调用 `SearchService`，`commerce-sync` 负责消费 `commerce.sync` 主题并调用 `VendureService`。两个工作进程都采用独立入口启动，并通过数据库状态实现抢占、重试和失败留痕。

## 11. 当前边界

消息未读、在线状态和断线补偿尚未落库，更完整的认证会话治理和更高自动化覆盖率还可以继续补强。事件驱动部分已经形成可运行链路，但当前仍以数据库轮询和日志排查为主，缺少更完整的消费监控和人工重放工具。
