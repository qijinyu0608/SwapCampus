# 数据库设计说明书

## 1. 数据库选型

- 主业务库：MySQL 8
- 认证库：SuperTokens 独立 PostgreSQL

选型原因：

- 商品、订单、校园服务、消息、举报、信用等核心数据以结构化关系为主
- Prisma 与 MySQL 配合成熟，便于课程项目快速迭代
- 认证数据独立存放，避免把会话能力和业务数据硬耦合在同一库中

## 3. 关键枚举与状态

### 3.1 用户相关

- `UserRole`：`USER / ADMIN`
- `VerificationStatus`：`PENDING / APPROVED / REJECTED`
- `AccountStatus`：`ACTIVE / BANNED`

### 3.2 商品交易相关

- `ProductStatus`：`PENDING / ON_SALE / SOLD / OFFLINE`
- `OrderStatus`：`PENDING / IN_PROGRESS / WAITING_REVIEW / COMPLETED / CANCELED`
- `MessageType`：`TEXT / IMAGE / VIDEO / EMOJI / ORDER_EVENT`
- `BehaviorEventType`：`VIEW / FAVORITE / UNFAVORITE / CONTACT / ORDER`

### 3.3 校园服务相关

- `CampusServiceIntent`：`REQUEST / OFFER`
- `CampusServiceCategory`：`ERRAND / AGENCY / GROUP_BUY / MOVING / TUTORING / SKILL / REPAIR / EVENT / OTHER / HELP`
- `CampusServiceListingStatus`：`OPEN / BUSY / PAUSED / ENDED / CANCELED`
- `CampusServiceOrderStatus`：`PENDING_CONFIRMATION / CONFIRMED / WAITING_COMPLETE_CONFIRM / COMPLETED / REJECTED / CANCELED / EXPIRED`

### 3.4 信用中心相关

- `CreditPointChangeType`：`EARN / SPEND / ADJUST`
- `CreditPointSourceType`：`SIGNIN / MISSION / REDEEM / ADMIN`
- `CreditRedeemOrderStatus`：`CREATED / FULFILLED / CANCELED / REJECTED`

## 4. 主要关系设计

- 用户与商品：一对多
- 商品与图片：一对多
- 用户与商品收藏：多对多，经 `Favorite`
- 商品与订单：一对多
- 订单与评价：一对多
- 订单与申诉：一对多
- 商品/订单/校园服务与会话：按上下文关联到 `Conversation`
- 会话与消息：一对多
- 用户与关注关系：多对多，经 `UserFollow`
- 用户与校园服务收藏：多对多，经 `CampusServiceFavorite`
- 校园服务发布与服务订单：一对多
- 用户与信用资产：一对一
- 用户与积分流水 / 任务领取 / 兑换记录：一对多

## 5. 主要表设计意图

### 5.1 `User`

承载用户基础身份、角色、信用分、实名状态和账号状态。

### 5.2 `StudentVerification`

承载真实姓名、学院、手机号、学生证照片等实名补充信息，与 `User` 一对一。

### 5.3 `Product` / `ProductImage`

承载商品标题、描述、价格、分类、成色、状态，以及多图上传后的图片元数据。

### 5.4 `Favorite`

当前已正式启用，用于登录用户商品收藏的账号级持久化关系。游客临时想要仍保存在浏览器本地。

### 5.5 `Order` / `Review` / `OrderAppeal`

承载商品交易闭环、评价记录和申诉处理。

### 5.6 `Conversation` / `Message`

承载商品、订单、校园服务等上下文下的统一消息结构，并支持 `ORDER_EVENT` 事件消息。

### 5.7 `CampusServiceListing` / `CampusServiceOrder`

把校园服务拆为“发布内容”和“具体成交/预约过程”两层，支持 `REQUEST / OFFER` 双向语义。

### 5.8 `CampusServiceFavorite`

用于登录用户收藏校园服务发布。

### 5.9 `UserBehavior` / `CampusServiceBehavior`

记录浏览、收藏、联系、下单等行为，为推荐排序和统计分析提供数据基础。

### 5.10 信用中心相关表

- `UserCreditAsset`：用户积分资产聚合
- `CreditPointLedger`：积分流水
- `CreditMissionClaim`：任务奖励领取记录
- `CreditRedeemOrder`：积分兑换记录

## 6. 索引与约束

重点约束包括：

- `User.studentId`、`User.email` 唯一
- `Favorite(userId, productId)` 联合唯一
- `CampusServiceFavorite(userId, listingId)` 联合唯一
- `UserFollow(followerId, followingId)` 联合唯一
- `Product` 按 `sellerId`、`status`、`category` 建索引
- `Order` 按 `buyerId`、`sellerId`、`status`、`autoConfirmAt` 建索引
- `OrderAppeal` 按 `orderId`、`status`、`appellantId`、`respondentId` 建索引
- `UserBehavior` 以 `userId / productId / eventType / createdAt` 为主建立聚合友好索引

## 7. 数据初始化口径

### 7.1 默认初始化

- 结构初始化：`npm run db:push -- --force-reset`
- 逻辑入口：`backend/prisma/init.ts`
- 当前行为：空库只建表，不自动导入演示数据

### 7.2 可选演示种子

如需重建演示环境，可执行：

```bash
npm run db:reset-and-seed-demo
```

该脚本会调用 `backend/prisma/demo-seed.ts` 中的演示数据计划。

当前可选演示种子规模：

- 用户：10
- 商品：30
- 校园服务：18
- 商品订单：6
- 校园服务订单：4
- 举报：4
- 审计日志：3

## 8. 当前文档口径

- “默认初始化结果”指 `make init` 后的空库建表状态
- “可选演示种子”指手动执行 `db:reset-and-seed-demo` 后可复现的数据集
- 运行中的真实统计会随着注册、发布、下单和发消息持续变化，不应写成固定常量

## 9. 当前实现结论

- 商品收藏已经不是预留表，而是现行能力
- 校园服务已完成 `listing + order` 双层建模
- 订单评价、申诉、关注关系、信用中心和媒体上传均已有数据库承载
- 认证主事实在 SuperTokens，会话与角色仍需和业务用户表保持同步
