# 数据库设计说明书

## 1. 数据库选型
MySQL 8

选型原因：
- 与课程任务书推荐技术栈一致
- 适合结构化交易数据建模
- Prisma 对 MySQL 支持成熟，便于代码与数据库模型同步维护

## 3. 关键字段说明
- `User.studentId`：学号，唯一
- `User.creditScore`：信用分，默认 60
- `User.role`：角色，当前区分 `USER`、`ADMIN`
- `User.isBanned`：封禁状态，影响登录和关键写操作
- `Product.status`：商品状态
- `Order.status`：订单状态
- `Message.type`：消息类型
- `CampusServiceListing.status`：校园服务发布状态
- `CampusServiceOrder.status`：校园服务订单状态
- `UserBehavior.eventType`：推荐行为事件

补充说明：
- `Product.tags`：使用逗号分隔字符串存储，前端读取时拆分为数组
- `StudentVerification.status`：当前使用 `PENDING` / `APPROVED` 表示审核态
- `Product.status`：当前演示版本重点使用 `PENDING` 与 `ON_SALE`
- `Conversation` 同时可关联普通订单或校园服务订单，用于统一会话结构

## 3.1 枚举与状态约束
- `ProductStatus`：`PENDING / ON_SALE / SOLD / OFFLINE`
- `OrderStatus`：`PENDING / IN_PROGRESS / WAITING_REVIEW / COMPLETED / CANCELED`
- `CampusServiceCategory`：`ERRAND / AGENCY / GROUP_BUY / HELP`
- `CampusServiceListingStatus`：`OPEN / BUSY / PAUSED / ENDED / CANCELED`
- `CampusServiceOrderStatus`：`PENDING_CONFIRMATION / CONFIRMED / WAITING_COMPLETE_CONFIRM / COMPLETED / REJECTED / CANCELED / EXPIRED`
- `MessageType`：`TEXT / IMAGE / EMOJI`
- `BehaviorEventType`：`VIEW / FAVORITE / UNFAVORITE / CONTACT / ORDER`

## 4. 关系概述
- 用户与商品：一对多
- 商品与图片：一对多
- 用户与订单：一对多
- 会话与消息：一对多
- 校园服务订单与会话：一对一
- 校园服务发布与订单：一对多
- 用户与行为日志：一对多
- 用户与实名信息：一对一

- 用户与审核日志：逻辑上一对多

## 5. 主要表设计意图
### 5.1 `users`
存储系统基础用户信息，包括学号、姓名、邮箱、角色、信用分和实名标记。

### 5.2 `student_verifications`
将实名审核信息从用户主表拆分，便于后续扩展审核状态、学院、联系电话等字段。

### 5.3 `products`
作为商品核心表，存储标题、描述、价格、分类、成色、状态、发布账号 ID 等字段。

### 5.4 `orders`
作为交易主表，记录商品、下单账号、发布账号、面交地点、备注与订单状态。

### 5.5 `conversations` / `messages`
用于支撑站内通讯场景。当前版本已使用该结构实现会话列表、消息明细和站内消息写库发送。

### 5.6 `reports`
为管理后台治理能力提供举报、处理结果、处理备注和封禁联动的数据基础。

### 5.7 `campus_service_listings`
用于承载校园跑腿、代办代取、拼单与临时帮忙等独立于二手商品流的服务发布内容。

### 5.8 `campus_service_orders`
用于承载校园服务中的一次具体成交、预约、确认与完结过程。

### 5.9 `user_behaviors`
记录浏览、收藏、取消收藏、联系、下单等行为事件，为推荐模块提供数据基础。

### 5.10 `favorites`
当前系统已启用 `Favorite` 表承接登录用户的正式收藏关系，用于跨端同步、详情页收藏状态展示、收藏页读取和推荐排序。游客模式下的临时“想要”仍保存在浏览器本地，不写入数据库。

## 5.11 索引与查询考虑
- `User.studentId`、`User.email`：唯一索引，支撑注册与登录查重
- `Favorite(userId, productId)`：联合唯一约束，避免重复收藏
- `UserBehavior` 已建立：
  - `(userId, createdAt)`
  - `(userId, productId, createdAt)`
  - `(productId, eventType)`
- 推荐、个人中心和治理列表中的聚合查询优先走这些索引与条件组合

## 6. 数据口径说明

- 种子基线：指执行 seed 后可稳定重建的初始演示数据
- 运行快照：指某次验收或联调时，系统真实运行中的统计结果

## 7. 数据初始化方式
- 结构初始化：`prisma db push`
- 数据初始化：`tsx prisma/seed.ts`

该方式适合课程设计当前阶段，便于快速重建演示环境。

## 8. 当前口径说明
- “种子基线”用于描述可重复构建的数据规模，是课程验收和文档统一口径
- “运行快照”用于描述某次联调或验收时的真实运行状态，会持续变化
- 文档中如果提到“想要/收藏”，需要区分：
  - 前端当前展示层：浏览器本地收藏
  - 后端当前推荐层：`UserBehavior` 行为记录
  - 数据库预留层：`Favorite` 表结构已保留，后续可启用
