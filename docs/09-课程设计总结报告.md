# 课程设计总结报告

## 1. 项目完成情况
本项目围绕校园二手交易场景，完成了从需求分析、概要设计、详细设计、数据库建模、前后端开发到 Docker 化部署的完整课程设计流程。

截至当前版本，系统已经具备以下可演示能力：
- 首页商品流读取真实数据库数据
- 注册新用户并保存到数据库
- 发布商品并在首页实时可见
- 创建订单并查看订单列表
- 查看会话并发送站内消息
- 在后台执行商品审核通过或下架
- Docker Compose 一键启动前后端、MySQL 和 MinIO
- 提供完整的 Markdown 文档交付包

当前系统属于“课程设计可交付版”，已达到可运行、可展示、可说明工程过程的目标。

## 2. 项目成果概述
### 2.1 业务成果
- 构建了游客、普通用户、管理员三类角色体系
- 实现了商品发布、浏览、沟通、下单、审核主链路
- 构建了校园信用、实名状态、举报、审核、封禁与恢复等治理闭环
- 基于 360 条商品种子数据、校园服务任务和真实用户数据完成了较完整的校园交易演示环境

### 2.2 工程成果
- 建立了前后端分离结构
- 全栈统一使用 TypeScript
- 使用 Prisma 管理数据库模型
- 使用 Docker Compose 管理运行环境
- 建立了 CI、文档、部署说明、开发记录与验收记录

## 3. 工程实践收获
- 体验了 Docs as Code 工作方式，文档与代码同步演进，而不是最后集中补写
- 建立了前后端分离的项目结构，并统一使用 TypeScript 降低沟通成本
- 使用 Docker Compose 管理 MySQL、MinIO、前端和后端，提高了演示环境复现能力
- 在开发过程中处理了端口冲突、Prisma engine 兼容、NestJS 依赖注入稳定性等工程问题，体现了软件工程中的定位、修复和验证思路
- 补充了 GitHub Actions CI、架构说明和容量估算，使课程设计不仅能跑，而且能体现工程化思考

## 4. 开发过程回顾
### 4.1 第一步：选型和架构确定
根据任务书和 PRD，优先满足核心模块和“种子数据不少于 200 条”的要求，选择了 React + NestJS + MySQL + Prisma + Docker Compose 的技术路线。

### 4.2 第二步：基础环境搭建
先完成仓库结构、Docker Compose、Prisma schema、前端 Vite 和后端 NestJS 骨架，确保系统具备持续扩展基础。

### 4.3 第三步：打通真实数据链路
先解决首页商品流和统计看板的数据读取，再补商品发布、消息和订单创建，保证系统不是静态页面演示。

### 4.4 第四步：页面与文档同步完善
在功能基本可用后，再统一前端风格、压缩默认信息密度、补齐文档内容和开发记录，避免文档与实现脱节。
- 在首页、收藏页、详情页等高频页面持续压缩默认态信息，逐步靠近闲鱼式“默认简洁、按需展开”的产品表达。

### 4.5 第五步：工程化交付收口
在核心链路可演示后，继续补充 IaC、CI、事件驱动预留、解耦说明和容量估算，保证老师从文档层面也能看到软件工程思想。

## 5. 关键设计反思
### 5.1 为什么采用前后端分离
前后端分离能够让页面交互与业务接口独立演进，便于在课程设计后续阶段继续补充实时通信、后台治理与权限控制。

### 5.2 为什么强调真实数据
如果只做静态页面，系统很难体现软件工程中的数据建模、状态流转和接口协作。本项目通过真实用户、商品、订单、消息和举报数据，使演示结果更接近真实产品。

### 5.3 为什么持续压缩默认态信息
参考闲鱼等成熟二手平台，首页和详情页默认不应一次性把所有说明铺开。本项目后期持续把长描述、规则、提示后置到折叠层，目的是让界面更像真实交易站点，而不是课程作业讲解页。

## 6. 当前不足
- 聊天模块已接入演示级 Socket.IO 实时推送，但尚未实现已读回执、在线状态和断线补偿等完整 IM 能力
- 当前测试覆盖率仍低于课程要求的理想值，需要补充更多服务层和接口层测试
- JWT 鉴权目前仍是演示态，尚未形成完整权限链路
- 个别页面仍可继续压缩默认态文字，进一步贴近成熟产品
- 部分表单类课程文档仍需结合学生个人信息做最终补填

## 7. 后续改进方向
- 完成聊天模块真实联调
- 增加更细粒度的处罚梯度、申诉与治理策略
- 补充自动化测试和覆盖率统计
- 进一步优化前端响应式体验和答辩演示流程
- 在有真实试用场景时引入缓存、消息队列和多实例部署

## 8. 课程设计收获总结
本次课程设计最大的收获并不只是“把一个网站做出来”，而是完整体验了需求分析、模块划分、数据库设计、接口联调、部署验证和文档归档这一整套软件工程流程。相比单纯拼页面，本项目更强调真实数据、真实状态和真实运行环境，这使我对“一个系统如何从想法走向可交付成品”有了更具体的认识。
