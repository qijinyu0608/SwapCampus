# 概要设计说明书

## 1. 系统架构
采用前后端分离架构：
- `frontend` 负责用户端和管理员页面
- `backend` 提供 REST API，并为 Socket.IO 扩展预留接口层
- `mysql` 负责业务数据持久化
- `minio` 负责图片对象存储

系统交互方式如下：
- 用户通过浏览器访问前端页面
- 前端通过 HTTP 调用后端接口获取商品、订单、用户数据
- 后端通过 Prisma 访问 MySQL
- MinIO 作为对象存储预留，用于后续商品图片上传与展示

当前课程设计版本已经验证：
- 首页商品流与统计看板可读取真实数据库数据
- 注册、发布商品、线下面交订单三条主链路可运行
- 站内消息支持真实写库发送与实时推送
- 商品详情、想要收藏、举报提交、资料编辑和信用摘要链路可运行
- 校园服务任务发布、接单、完成与消息联动可运行
- 管理后台支持商品审核通过与下架
- 举报处理、用户封禁与解除封禁闭环已完成
- Docker Compose 可启动完整演示环境

### 1.1 软件工程设计思想
当前版本重点体现以下软件工程思想：
- 分层设计：前端、控制器、服务层、数据层职责分离
- 解耦设计：页面通过统一 API 服务访问后端，控制器不直接访问数据库
- Docs as Code：文档与代码同仓库维护，降低实现与文档脱节风险
- IaC：通过 `docker-compose.yml` 和 Prisma Schema 管理运行环境与数据库结构
- CI 思路：通过 GitHub Actions 执行后端测试和前端构建
- 事件驱动预留：消息发送、商品审核、订单创建等行为可继续演进为领域事件

### 1.2 事件驱动与异步扩展思路
当前项目核心链路采用同步 HTTP，保证课程设计交付时的简单性和稳定性；同时在架构设计上预留如下事件：
- `ProductPublished`
- `OrderCreated`
- `MessageSent`
- `ProductStatusChanged`

后续可引入 Redis Stream、RabbitMQ 或 Kafka 作为消息队列，用于异步通知、审核日志、推荐计算与搜索索引更新。

## 2. 模块划分
- 用户与认证模块
- 商品模块
- 订单与评价模块
- 消息模块
- 校园服务模块
- 推荐与行为模块
- 想要与本地偏好模块
- 信用与实名模块
- 举报与审核模块
- 管理后台模块

### 2.1 用户与认证模块
负责注册、登录、会话维护、实名信息基础维护。当前已接入 `SuperTokens` 会话体系，并完成注册、登录、守卫与角色校验主链路。

### 2.2 商品模块
负责商品发布、审核规则读取、商品状态维护、商品列表、推荐流、详情页信号聚合与看板统计。当前已完成商品发布、首页商品流、推荐排序、详情页卖家画像、商品总数与待审核数统计。

### 2.3 订单模块
负责普通用户发起订单、线下面交约定、取消订单、确认完成、评价提交和订单列表查询。当前订单流程不包含线上付款、发货、物流和收货环节，重点围绕校内当面交易闭环展开。

### 2.4 消息模块
负责站内交易双方会话和消息推送。当前已完成会话列表、消息明细、站内消息写库发送、校园服务任务消息联动，并接入基于房间的 Socket.IO 演示级实时推送。

### 2.5 校园服务模块
负责承接校园跑腿、代办、拼单、临时帮忙等与二手商品主流不同的服务场景。当前已完成任务发布、接单、完结、消息联动和独立页面承载。

### 2.6 推荐与行为模块
负责记录浏览、收藏、联系、下单等行为，并结合分类偏好、标签偏好和热度生成首页推荐结果。当前已完成基础行为记录与推荐排序逻辑。

### 2.6.1 想要与本地偏好模块
负责保存想要列表、最近浏览和轻量偏好画像。当前版本对登录用户使用后端 `Favorite` 表承接正式收藏关系，对游客模式保留浏览器本地临时想要，并把普通用户的关键行为同步写入后端推荐行为表。

### 2.7 信用与实名模块
负责实名状态、信用分、成交表现、回复率和评分等可信度信息的展示与治理。当前已完成信用分、实名状态、个人中心信用摘要、详情页卖家可信度面板和治理基础展示，后续可补更细化评分来源。

### 2.8 管理后台模块
负责商品审核、举报处理、异常用户识别和操作留痕。当前已完成后台总览、商品审核、举报处理、用户封禁和解除封禁、审核日志读取能力；后续继续细化处罚梯度与申诉策略。

## 3. 部署结构
本地开发与演示环境通过 Docker Compose 编排 MySQL、MinIO、后端和前端服务。

### 3.1 服务组成
- `frontend`：端口 `5178`
- `backend`：端口 `3001 -> 3000`
- `mysql`：端口 `3306`
- `minio`：端口 `9000 / 9001`
- `db-init`：一次性数据库初始化任务，用于推送 Prisma schema 和导入种子数据

### 3.2 部署特点
- 使用统一的 `docker-compose.yml` 组织服务
- 后端容器在构建阶段执行 `npx prisma generate`
- 数据库通过 `prisma db push` 初始化结构，通过 `seed.ts` 导入样例数据
- 前端容器采用 `build -> dist -> nginx` 的静态托管方式
- 宿主机前端生产构建固定使用 `Node 20` 执行 `tsc` 与 `vite build`

### 3.3 工程考虑
- 将后端外部端口调整为 `3001`，避开本机现有 `3000` 端口占用
- 使用容器内生成 Prisma Client 的方式处理宿主机与容器运行时差异
- 文档与代码共同纳入仓库，满足 Docs as Code 要求
- 使用 GitHub Actions 预留基础 CI，保证后端测试和前端构建在提交后可自动验证
- 当前部署适合课程答辩和小规模试用，可承载几十级并发访问；如需扩容，可继续增加缓存、消息队列和多实例后端
