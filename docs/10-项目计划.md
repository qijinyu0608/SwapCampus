# 项目计划

## 1. 推进方式

本项目没有采用前期一次性写完全部方案、后期再集中落地的推进方式，而是按“小步迭代、实现即验证、变更即同步文档”的节奏持续推进。这样做的目的，是让课程设计中的需求、代码、测试和交付材料始终保持同一口径，减少后期集中补救带来的失真。

## 2. 已完成阶段

### 阶段一：基础工程

本阶段完成了前后端目录划分、Docker Compose 基础环境、Prisma 数据模型和前端页面骨架，为后续主链路开发建立了稳定底座。

### 阶段二：主链路

本阶段重点打通用户侧交易主链路，完成了商品浏览、搜索、详情、注册登录、商品发布，以及订单创建与消息联动等能力，使系统从展示原型进入可操作状态。

### 阶段三：治理与扩展

在核心交易链路稳定后，系统继续向治理和扩展能力推进，补齐了后台审核、举报与封禁、校园服务、收藏持久化、信用中心、订单评价与申诉等模块，使课程设计目标从“能用”进一步发展到“可治理、可说明”。

### 阶段四：交付收口

当前阶段主要围绕交付收口展开，重点处理对象存储与图片上传的稳定性、文档归档整理、运行截图、验收记录和部署说明，确保老师在不深入阅读源码的情况下也能理解系统完成度。

## 3. 当前进行中

当前仍在进行的工作主要有两项：一是持续核对文档与当前实现的一致性，避免页面、接口和数据口径出现旧描述；二是进一步精修演示脚本和答辩材料，使现场展示路径更紧凑、证据更完整。

## 4. 后续增强

结合现有完成度，后续增强方向已经比较明确，包括补齐更完整的 IM 能力、提升前端自动化测试覆盖率，以及细化风控与治理策略。这些内容不影响当前课程设计交付，但属于后续继续迭代时最有价值的工作。
