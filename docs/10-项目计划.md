# 项目计划

## 阶段划分与实际推进记录
本项目采用“小步迭代、边实现边验证、边更新文档”的推进方式。每完成一轮关键功能或界面收口，都同步更新需求、设计、测试、部署和验收文档，避免课程设计后期出现“代码与文档口径脱节”。

### 阶段一：需求与设计
- 根据课程任务书和选题 PRD 明确 6 个必做模块
- 确定技术栈为 React 18 + TypeScript + NestJS + Prisma + MySQL + Docker Compose
- 输出设计说明与实现计划，明确前后端分工边界

### 阶段二：基础工程搭建
- 在 `SwapCampus` 目录建立独立仓库
- 配置 `frontend`、`backend`、`mysql`、`minio` 四类资源
- 解决 Node/npm 环境问题，完成依赖安装与本地构建

### 阶段三：核心链路开发
- 打通首页商品流与统计看板接口
- 打通用户注册接口和账号登录流程
- 打通商品发布接口
- 打通订单创建与订单列表接口
- 导入 360 条商品种子数据，满足并高于课程数据规模要求

### 阶段四：页面与交互完善
- 首页改造成面向答辩展示的产品首页
- 登录页、发布页、个人中心页接入真实接口
- 消息页与后台页从空白壳升级为具备真实业务语境的可操作页面
- 统一视觉风格为橙色主色的校园二手产品表达
- 持续压缩默认态信息密度，使首页、详情页、消息页、收藏页更接近闲鱼式“默认简洁、按需展开”的交互模式

### 阶段五：文档与交付收口
- 文档改为 Markdown 扁平目录
- 按真实实现更新需求、设计、测试、部署、用户手册与总结
- 补充开发记录与验证证据，保证老师不看代码也能理解系统完成度
- 输出页面截图、接口验收记录和答辩提纲
- 对照课程任务书补查缺失项，补强阶段计划、中期检查、验收记录和交付清单中的工程化表达
- 建立文档管理规范，明确标准、更新触发规则、追溯关系和版本维护机制

  - Docker Compose 一键部署、种子数据导入、页面截图归档、验收记录整理

  - 文档与最新实现口径持续对齐
