# 团队分工与贡献说明

## 建议分工

若按常规课程设计小组组织，本项目适合采用四类职责分工：组长负责项目推进、需求跟踪与答辩协调；前端负责人负责用户端与后台页面实现、联调和交互收口；后端负责人负责接口、数据库、审核、消息与业务规则实现；测试与文档负责人负责测试执行、缺陷跟踪和交付材料维护。这样的分工方式与当前系统的模块边界基本一致，便于把责任落实到具体产出。

## 贡献记录方式

项目贡献主要通过两类证据记录：一类是 Git 提交历史，用于反映代码实现、修复和重构过程；另一类是文档修改记录，用于说明需求调整、测试验证和交付整理过程。两者结合后，能够较完整地还原每位成员在课程设计中的实际投入。

## 当前项目实际贡献类型

从当前项目状态看，实际贡献大致集中在三个方面。其一是产品与界面表达，完成了首页、发布页、消息页、个人中心和后台页的统一视觉收口；其二是后端与数据库实现，完成了注册登录、商品发布、订单创建、消息发送、后台审核以及演示数据构建；其三是测试与运维保障，完成了本地构建、Docker Compose 启动、接口联调和课程设计文档同步维护。若需要进一步细化到个人层面，可直接结合 Git 历史和文档修改记录拆分统计。
