# 开发记录

## 记录目的
本文件用于保留课程设计开发过程中的关键决策、问题定位、修复动作和验证结果，体现“逐步开发、逐步验证、逐步完善文档”的软件工程过程。

## 阶段记录

### 2026-06-02：项目初始化
确定项目独立目录为 `SwapCampus`，建立前后端、文档、数据库与基础设施目录，并选定 React、NestJS、Prisma、MySQL 与 Docker Compose 作为技术路线。同步补齐第一版课程设计文档骨架，为后续实现和交付留出统一入口。

### 2026-06-02：环境问题处理
开发环境初始化时发现本机只有 `node` 而缺少 `npm`，随后通过 Homebrew 补齐完整 Node 工具链，并修复 Vite 环境类型声明问题，确保前端能够正常构建。

### 2026-06-02：Docker 与 Prisma 联调
首次联调 Docker Compose 时发现 `3000` 端口被占用，因此将后端外部端口改为 `3001`。随后又定位到 Prisma Client 在容器与宿主机之间的运行时兼容问题，通过在 `backend/Dockerfile` 中安装 `openssl` 并在构建阶段显式执行 `npx prisma generate` 完成修复。

### 2026-06-02：后端主链路打通
后端主链路开发阶段，先后打通首页商品列表与统计接口、首批商品种子数据、注册接口、商品发布接口，以及订单创建和订单列表接口，使前端能够围绕真实数据流继续联调。

### 2026-06-02：依赖注入问题定位
容器运行过程中曾出现 `ProductsService`、`AuthService`、`OrdersService` 对应控制器注入失败的问题，随后采用显式 `@Inject(...)` 方式修复依赖注入，并重新验证商品流、注册和订单创建接口均已恢复可用。

### 2026-06-02：前端产品化改造
前端从早期的功能壳逐步收口为更接近真实产品的界面：首页由简单列表演进为商品流首页，登录页接入真实注册与登录，发布页接入真实发布接口，个人中心开始展示当前用户和订单信息，消息页与后台页也从空白占位升级为带业务语境的可演示页面。

### 2026-06-02：消息与后台真实化
为消息模块补充会话列表与消息明细接口，为后台模块补充管理员总览接口。联调中又发现 Prisma schema 缺少 `Conversation` 与 `Message` 的关系字段，补齐后重新执行 `db push` 并重建容器，最终验证消息页和后台页均已接上真实数据。

### 2026-06-02：功能闭环补齐与交付收口
继续补齐 `POST /api/messages/conversations/:id` 和 `PATCH /api/admin/products/:id/status` 等关键接口，前端消息页接入真实发送能力，后台页接入审核通过与下架按钮，形成最小治理闭环。同时对首页与发布页做视觉收口，使其更接近校园二手交易平台的常见表达。至此，会话读取、消息发送、后台审核等主路径均已能通过真实接口验证。

### 2026-06-02：软件工程设计思想补强
在交付视角下复查后发现，文档虽然已经覆盖功能，但对分层设计、解耦、基础设施即代码、持续集成和事件驱动预留等工程化表达还不够充分。随后补充 `infra/architecture.md`，新增 `.github/workflows/ci.yml`，并把相关说明同步写入概要设计、详细设计、部署手册、测试报告和总结报告中。

### 2026-06-02：页面验收证据归档
为了补齐直观验收证据，使用系统 Chrome 的 headless 模式为首页、登录、详情、发布、消息、个人中心和后台生成运行截图，并统一归档到 `artifacts/screenshots`。随后在 `README.md` 与验收记录中补充引用，方便不运行代码的情况下直接查看界面效果。

### 2026-06-02：文档精修
文档精修阶段重点处理“文档像模板、实现像另一套系统”的问题。测试报告开始纳入真实验证记录，项目计划改为体现阶段推进过程的文本，概要设计、详细设计和数据库设计与当前实现重新对齐，用户手册、部署手册和总结报告也从占位稿改写为当前系统状态说明。

### 2026-06-03：治理闭环与账号体系补强
完成举报处理结果与 `BAN_USER / UNBAN_USER` 的联动，补齐被封禁账号在登录、举报、发布、下单和消息发送等环节的拦截逻辑，并重新明确普通用户“既是买家也是卖家”的统一账号模型，避免角色拆分造成的错误表达。

### 2026-06-03：首页信息架构连续收口
首页信息架构经历了一轮连续收口：保留一级分类常驻、二级分类按需展开，商品卡压缩为以价格和卖家信息为核心的紧凑表达，活动区重排为更接近日常交易平台的主副卡结构，同时删除重复分类入口并修正窄屏下的浏览顺序，减少“课程原型感”。

### 2026-06-03：详情页默认态精修
详情页调整重点在于降低默认态的信息噪声。首屏保留价格、交易参考、卖家信用和主要动作，把想要、举报、浏览量、分类等非核心信息下沉到折叠区，并统一相关商品卡的视觉表达。

### 2026-06-03：文档改为持续迭代维护
根据课程设计要求，文档维护被正式提升为一等交付物，不再留到开发尾声统一补写，而是在每轮关键实现和验收后立即同步更新。校对重点集中在项目计划、部署手册、交付清单、用户手册与验收记录之间的一致性。

### 2026-06-03：文档治理与版本规范补齐
为了让文档治理规则不再停留在口头约定，新增 `18-文档管理与版本规范.md`，并把数据表达统一为“种子基线 + 运行快照”的双口径，同时以追溯矩阵作为需求、实现、测试与验收证据的总索引。

### 2026-06-03：会话切换与看板默认态收口
为了提升现场演示体验，头部增加了 `退出登录`，并将其行为调整为清空本地登录态后回到首页。个人中心与后台也重新收口默认态，优先展示摘要和轻量看板，把次级明细放入折叠区，减轻页面堆砌感。

### 2026-06-03：消息发送归属修复
联调过程中发现消息页曾错误地用 `senderId` 奇偶数判断消息归属，导致当前用户发送的内容可能被渲染成对方消息。随后改为基于 `message.senderId === currentUser.id` 判断，并重新构建前端，确保运行态与源码一致。

### 2026-06-03：消息实时推送补齐
消息系统继续向实时化推进：后端补充 Socket.IO 网关，支持通过 `message:join` 订阅会话房间；消息写入后广播 `message:new`；前端则在可见会话中接收推送并实时更新左侧预览。该能力目前已完成演示级验证。

### 2026-06-03：发布页默认态收口
发布页去掉了会打断主路径的顶部统计卡，把标题、分类、价格、成色和描述收敛为首屏主表单，标签与补充信息下沉到折叠区域，使页面更接近真实交易平台的快速发布体验。

### 2026-06-03：首页活动区与校园服务模块补齐
继续调整首页活动区布局，压缩分类栏宽度，把视觉重心让给活动主区，并把校园跑腿、代办代取、校内拼单和临时帮忙等内容独立抽成 `校园服务` 子模块，不再直接混入二手商品主流。对应页面也补充了服务热度、热门委托和规则提示。

### 2026-06-03：文档口径与当前实现再对齐
复查项目计划和阶段材料时，发现仍残留“Socket.IO 未完成”的旧表述。结合当前网关实现和浏览器实时收信结果，统一改为“演示级实时推送已完成，完整 IM 能力仍待增强”，并同步梳理“已经完成”和“后续增强”的边界。

## 当前结论
截至当前版本，项目已经达到课程设计“可交付版本”：
系统能够稳定启动，核心链路可以现场演示，页面风格基本统一，文档也能够独立说明项目目标、结构、流程与完成度。开发记录本身也较完整地体现了迭代实现、阶段验证和文档同步维护的过程。

## 仍待增强
后续仍可继续增强的方向主要包括：已读回执、在线状态和断线补偿等完整 IM 能力，更细化的处罚梯度与申诉策略，更高的自动化测试覆盖率，以及更成熟的答辩稿组织方式。
