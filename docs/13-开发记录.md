# 开发记录

## 记录目的
本文件用于保留课程设计开发过程中的关键决策、问题定位、修复动作和验证结果，体现“逐步开发、逐步验证、逐步完善文档”的软件工程过程。

## 阶段记录

### 2026-06-02：项目初始化
- 确定项目独立目录为 `SwapCampus`
- 建立前后端、文档、数据库与基础设施目录
- 选择 React + NestJS + Prisma + MySQL + Docker Compose 技术路线
- 完成第一版课程文档骨架

### 2026-06-02：环境问题处理
- 发现本机只有 `node`，缺少 `npm`
- 使用 Homebrew 安装完整 Node 工具链
- 修复 Vite 环境类型声明问题，确保前端可构建

### 2026-06-02：Docker 与 Prisma 联调
- 首次启动 Docker Compose 时发现 `3000` 端口被占用
- 将后端外部端口改为 `3001`
- 发现 Prisma Client 在容器中与宿主机运行时不兼容
- 在 backend Dockerfile 中安装 `openssl`
- 在容器构建阶段显式执行 `npx prisma generate`
- 修复后端读取数据库依赖的容器运行时问题

### 2026-06-02：后端主链路打通
- 打通首页商品列表与统计接口
- 导入首批商品种子数据并打通商品流接口
- 打通注册接口
- 打通商品发布接口
- 打通订单创建与订单列表接口

### 2026-06-02：依赖注入问题定位
- 在容器运行中发现 `ProductsService`、`AuthService`、`OrdersService` 对应控制器存在注入失败问题
- 采用显式 `@Inject(...)` 方式修复控制器和服务依赖注入
- 重新验证商品流、注册、订单创建接口均可用

### 2026-06-02：前端产品化改造
- 首页从简单表格页升级为具备叙事结构的产品首页
- 登录页接入真实注册与账号登录流程
- 发布页接入真实商品发布接口
- 个人中心展示当前登录用户与订单列表
- 消息页和后台页从空白壳升级为带真实业务语境的演示页面

### 2026-06-02：消息与后台真实化
- 为消息模块补充会话列表接口与消息明细接口
- 为后台模块补充管理员总览接口
- 发现 Prisma schema 中缺少 `Conversation` 与 `Message` 关系字段
- 补齐 schema 关系后重新 `db push` 和构建容器
- 验证消息页已能读取真实会话数据，后台页已能读取真实统计数据

### 2026-06-02：功能闭环补齐与交付收口
- 为消息模块补充 `POST /api/messages/conversations/:id`
- 为后台模块补充 `PATCH /api/admin/products/:id/status`
- 前端消息页接入真实发送动作，发送后刷新会话与消息列表
- 前端后台页接入审核通过与下架按钮，形成最小治理闭环
- 将首页与发布页视觉调整为更贴近校园二手交易平台的橙色商品流表达
- 使用真实接口完成最终验收：
  - 会话列表与消息明细可读取真实数据
  - 后台审核接口可执行通过与下架动作
  - 当时阶段性统计值已能验证首页、后台和审核链路打通

### 2026-06-02：软件工程设计思想补强
- 发现课程设计文档虽然覆盖功能，但对分层、解耦、IaC、CI、事件驱动预留和容量设计表达不足
- 补充 `infra/architecture.md` 作为统一工程架构说明
- 新增 `.github/workflows/ci.yml`，把“持续集成”从文档设想落实为实际仓库资产
- 在概要设计、详细设计、部署手册、测试报告和总结报告中同步加入工程化说明
- 对前端导航和登录入口页做二次产品化设计，进一步贴近闲鱼式校园二手产品界面

### 2026-06-02：页面验收证据归档
- 使用系统 Chrome headless 模式为首页、登录、详情、发布、消息、个人中心、后台生成截图
- 将截图统一归档到 `artifacts/screenshots`
- 在 README 与验收记录中加入截图引用，保证老师不运行代码也能看到最终界面结果

### 2026-06-02：文档精修
- 将测试报告改为包含真实验证记录的文档
- 将项目计划改为体现阶段推进的开发记录式文档
- 将概要设计、详细设计、数据库设计与当前实现保持一致
- 将用户手册、部署手册、总结报告从“占位”改为“真实系统状态”

### 2026-06-03：治理闭环与账号体系补强
- 完成举报处理结果直接触发 `BAN_USER / UNBAN_USER`
- 补齐被封禁账号的登录拦截、举报拦截、发布拦截、下单拦截和消息写入拦截
- 对齐普通用户“既是买家也是卖家”的统一账号模型，避免角色拆分带来错误表达
- 更新验收记录，补充用户治理真实闭环验证步骤

### 2026-06-03：首页信息架构连续收口
- 首页从“展示型课设首页”继续收紧到更接近闲鱼的浏览入口结构
- 保留一级分类常驻、二级分类按需展开
- 补充首页一级分类浏览入口，并将左侧分类标题压缩为短标题，降低原型感
- 商品卡压缩为“封面弱标签 + 价格 + 卖家与地点”三层核心信息
- 去掉首屏冗余辅助条，避免首页搜索区被切成过多段落
- 将分类右侧重排为“活动快捷入口 + 校园专题卡片”，商品流统一放在其下方
- 收紧活动区文案与配色，避免出现过重的促销海报感
- 修正窄屏顺序，确保首页仍然先看到活动区，再看到分类与商品
- 删除首页顶部与左侧重复的一套分类入口，只保留左侧分类栏作为唯一主分类入口
- 将首页上半区调整为左右等宽，减少一侧过窄造成的信息失衡

### 2026-06-03：详情页默认态精修
- 发现原详情页默认态暴露过多“系统词”和弱信息，不符合真实交易站点的默认观感
- 将详情页首屏收口为价格、少量交易参考、卖家信用和两个主动作
- 将想要、举报、浏览量、分类等非核心信息下沉到折叠区，减少默认打扰
- 将相关商品卡同步到首页同一套紧凑商品卡表达

### 2026-06-03：文档改为持续迭代维护
- 根据最新课设要求，将文档维护提升为一等交付物
- 不再将文档工作留到开发尾声，而是在每轮关键实现和验收后立即更新相关文档
- 重点补查项目计划、中期检查、部署手册、交付清单、用户手册与验收记录的一致性

### 2026-06-03：文档治理与版本规范补齐
- 将“文档管理与版本规范”从隐含约定提升为显式文档，新增 `18-文档管理与版本规范.md`
- 把文档口径统一改为“种子基线 + 运行快照”双口径，避免运行中的真实库继续增长后造成数字失真
- 将追溯矩阵作为需求、实现、测试和验收证据的总索引，强化文档可追溯性

### 2026-06-03：会话切换与看板默认态收口
- 在头部补充 `退出登录`，解决同机演示时退出当前账号不够直接的问题
- `退出登录` 调整为清空本地登录态后回到首页，头部同步恢复为未登录状态
- 个人中心改为“摘要与轻量看板优先、资料与信用明细后置折叠”的默认态
- 个人中心在信用摘要接口暂未返回时，仍使用账号与订单信息生成基础看板，避免页面退化成纯资料页
- 后台首屏保留运营摘要与轻量看板，治理清单继续放在折叠区中，降低课程作业式堆卡片观感

### 2026-06-03：消息发送归属修复
- 发现消息页曾错误使用 `senderId` 奇偶数决定气泡左右位置
- 该逻辑会导致“当前用户刚发送的消息”被渲染成“对方消息”
- 将消息归属改为按 `message.senderId === currentUser.id` 判断
- 重新执行前端生产构建并同步 Docker 前端容器，保证运行态与源码一致
- 消息页默认态继续收口：移除顶部统计条，游客态改为只读提示卡，消息气泡按真实聊天流收窄显示

### 2026-06-03：消息实时推送补齐
- 后端新增 Socket.IO 消息网关，支持客户端通过 `message:join` 加入 `conversation:{id}` 房间
- `POST /api/messages/conversations/:id` 继续先写入 `Message` 表，再广播 `message:new`
- 前端消息页订阅可见会话，收到推送后实时追加当前会话消息并更新左侧会话预览
- 完成 Socket.IO 客户端直连验证与浏览器消息页无刷新接收验证

### 2026-06-03：发布页默认态收口
- 发布页去掉顶部统计卡，避免首屏先看到“课设看板”而不是主表单
- 将标题、分类、价格、成色、描述收敛为首屏默认主路径
- 标签移动到 `补充信息` 折叠区，常用写法、发布提示和规则继续保留在右侧但默认不抢首屏
- 重新压缩发布页左右布局和表单间距，使其更接近真实交易平台的快速发布页

### 2026-06-03：首页活动区与校园服务模块补齐
- 发现首页活动区在分栏浏览宽度下出现细长竖卡堆叠，整体观感偏离闲鱼首页的主副卡活动结构
- 将首页分类栏进一步压缩为窄栏，把主要横向空间留给右侧活动主区
- 将活动区重排为更接近闲鱼的“主活动卡 + 四个副卡”结构，避免首屏出现过多白底长条卡片
- 在首页活动快捷入口中补充 `校园服务`
- 将校园跑腿、代办代取、校内拼单、临时帮忙独立抽成 `校园服务` 子模块，不再直接混入二手商品主流
- 为 `校园服务` 页面补充服务热度看板、热门委托列表与规则提示，保持和主站一致的简洁信息密度

### 2026-06-03：文档口径与当前实现再对齐
- 复查中期检查报告与项目计划，发现其中仍保留“Socket.IO 未完成”的旧叙述
- 结合当前 `messages` 模块网关实现和浏览器实时收信结果，改为“演示级实时推送已完成，完整 IM 能力仍待增强”的准确表述
- 对齐“当前已实现”和“后续增强项”的边界，避免答辩材料出现自相矛盾
- 顺手清理前端页面中已无实际用途的导入，减少交付版本中的实现噪音
