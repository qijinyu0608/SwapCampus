# 当前系统页面与功能清单

## 1. 文档目的

本文档用于按当前代码真实状态，重新整理 SwapCampus 已具备的页面、功能和主链路。

它不沿用旧版课程文档中的理想化表述，而以当前前端路由、页面实现和实际接口能力为准，回答三个问题：

1. 当前系统到底有哪些页面
2. 每个页面可以做什么
3. 整个系统已经具备哪些业务能力

本文档适合作为：

- 当前版本功能定义总览
- 页面清单与答辩说明材料
- 后续页面改版、功能重构时的对照基线

## 2. 系统总体定义

当前系统是一个面向校内师生的校园闲置交易与校园服务平台，主要包含四条业务主链路：

1. 二手商品交易链路
2. 用户与个人中心链路
3. 校园服务链路
4. 后台治理链路

### 2.1 二手商品交易链路

- 浏览商品
- 搜索商品
- 查看商品详情
- 想要 / 收藏商品
- 发起商品沟通
- 创建订单
- 约定线下面交
- 完成交易
- 提交评价

### 2.2 用户与个人中心链路

- 登录 / 注册
- 查看个人主页
- 查看与编辑个人资料
- 查看信用摘要
- 查看我发布的商品
- 查看我收藏的商品
- 查看我的订单

### 2.3 校园服务链路

- 浏览校园服务任务
- 发布校园服务任务
- 接单
- 完成任务
- 跳转消息会话继续沟通

### 2.4 后台治理链路

- 查看运营概览
- 审核商品
- 管理订单
- 管理校园服务任务
- 处理举报
- 封禁 / 解封用户
- 查看操作日志

## 3. 角色定义

当前系统长期只保留三类角色语义：

- 游客
- 普通用户
- 管理员

### 3.1 游客

- 可浏览首页、搜索页、商品详情页、公开用户主页、校园服务列表
- 不可发布商品、发消息、创建订单、进入个人中心、进入后台

### 3.2 普通用户

- 具备买家和卖家双重能力
- 可发布商品、收藏、沟通、下单、评价
- 可查看和维护自己的资料、商品、订单、收藏
- 可发布、接受、完成校园服务任务

### 3.3 管理员

- 可进入后台进行治理操作
- 可管理商品、订单、校园服务、举报与用户状态

## 4. 页面清单

以下页面以当前前端路由为准。

### 4.1 首页 `/`

页面职责：

- 作为系统默认入口页
- 展示分类入口、活动区和推荐商品流
- 承担从浏览到搜索、从推荐到详情的首轮分发功能

当前功能：

- 顶部搜索框
- 分类快捷入口
- 首页活动 / 运营展示区
- “猜你喜欢”推荐商品流
- 登录用户信息摘要区
- 登录用户订单、收藏、消息快捷入口
- 商品卡片支持进入详情
- 商品卡片支持想要 / 取消想要

访问角色：

- 游客可访问
- 普通用户可访问
- 管理员可访问

对应主链路：

- 浏览商品
- 进入搜索
- 进入详情
- 进入收藏
- 进入消息
- 进入订单

### 4.2 搜索页 `/search`

页面职责：

- 承接首页搜索动作
- 作为商品关键词检索页

当前功能：

- 根据关键词搜索商品
- 展示搜索结果商品流
- 输入新关键词重新搜索
- 商品卡片支持想要 / 取消想要
- 商品卡片支持进入商品详情

访问角色：

- 游客可访问
- 普通用户可访问
- 管理员可访问

对应主链路：

- 搜索商品
- 从搜索结果进入详情

### 4.3 校园服务页 `/campus-services`

页面职责：

- 独立承接校园跑腿、代办、拼单、临时帮忙等非商品交易需求

当前功能：

- 浏览校园服务任务
- 查看待接热度和常用路线
- 查看常用地点
- 按分类、状态、关键词筛选任务
- 发布服务任务
- 接受任务
- 完成任务
- 跳转到服务消息会话

访问角色：

- 游客可浏览任务
- 普通用户可发布、接单、完成
- 管理员可访问，但治理主入口在后台

对应主链路：

- 浏览任务
- 发布任务
- 接单
- 完成任务
- 消息联动

### 4.4 想要页 `/favorites`

页面职责：

- 集中展示用户已经想要 / 收藏的商品

当前功能：

- 展示收藏商品列表
- 区分“还在售”和“已失效”
- 进入商品详情
- 空态时返回首页继续浏览

访问角色：

- 主要面向普通用户
- 游客可见路径语义，但不具备完整账号级收藏能力

对应主链路：

- 收藏沉淀
- 回访商品
- 从收藏进入交易

### 4.5 商品详情页 `/products/:id`

页面职责：

- 展示单个商品的完整信息
- 承接从浏览到沟通、下单、举报的核心转化

当前功能：

- 查看商品标题、价格、分类、成色、标签、描述、图片
- 查看卖家公开信息与信用摘要
- 查看交易参考与合规提示
- 想要 / 取消想要
- 发起会话
- 创建订单
- 举报商品或举报用户
- 查看对方在售商品
- 查看相似推荐

访问角色：

- 游客可浏览详情
- 普通用户可继续执行收藏、沟通、下单、举报
- 管理员可浏览，但治理操作在后台

对应主链路：

- 查看详情
- 发起沟通
- 创建订单
- 举报治理

### 4.6 用户公开主页 `/users/:id`

页面职责：

- 展示某个卖家的公开资料与其在售商品

当前功能：

- 查看用户昵称
- 查看信用摘要
- 查看该用户正在出售的商品
- 进入商品详情

访问角色：

- 游客可访问
- 普通用户可访问
- 管理员可访问

对应主链路：

- 浏览卖家
- 继续查看该卖家商品

### 4.7 发布商品页 `/publish`

页面职责：

- 承接商品发布

当前功能：

- 填写标题、分类、成色、价格、标签、描述
- 查看发布规则
- 查看常用写法模板
- 查看补充说明
- 提交商品发布

访问角色：

- 仅普通用户

对应主链路：

- 发布商品
- 进入审核流

### 4.8 消息页 `/messages`

页面职责：

- 作为商品交易和校园服务任务的统一站内沟通入口

当前功能：

- 会话列表
- 消息明细
- 发送文本消息
- 基于 Socket.IO 的演示级实时更新
- 从订单、商品、校园服务上下文进入对应会话
- 会话中跳转商品详情

访问角色：

- 仅普通用户

对应主链路：

- 沟通
- 订单后续协商
- 服务任务协商

### 4.9 我的页 `/profile`

页面职责：

- 作为普通用户的个人中心主页面

当前功能：

- 查看个人主页摘要
- 查看信用摘要
- 查看“我发布的宝贝”
- 查看“我收藏的宝贝”
- 查看“线下面交订单”
- 查看个人资料摘要
- 对订单进行后续操作：
  - 去商品详情
  - 去消息会话
  - 确认面交信息
  - 取消订单
  - 完成订单
  - 提交评价

访问角色：

- 仅普通用户

对应主链路：

- 管理我的商品
- 管理我的收藏
- 管理我的订单
- 管理我的资料

### 4.10 个人资料详情页 `/profile/detail`

页面职责：

- 展示更完整的个人资料与信用详情

当前功能：

- 查看个人资料详情
- 查看信用摘要
- 返回个人中心

访问角色：

- 仅普通用户

对应主链路：

- 查看资料详情

说明：

- 当前这个页面更偏查看页
- 真正的资料编辑主入口仍在个人中心内部

### 4.11 登录 / 注册页 `/login`

页面职责：

- 承接认证入口

当前功能：

- 登录
- 注册
- 登录后按来源页回跳
- 管理员登录后进入后台

访问角色：

- 游客可访问

对应主链路：

- 登录
- 注册
- 权限进入

### 4.12 后台页 `/admin`

页面职责：

- 承接管理员的运营与治理工作

当前功能：

- 运营概览
- 商品列表与审核 / 上下架
- 订单管理
- 校园服务任务管理
- 举报列表与处理
- 用户治理
- 操作日志查看

访问角色：

- 仅管理员

对应主链路：

- 审核治理
- 风险处理
- 运营观察

## 6. 当前版本的边界与不成熟项

虽然页面和主链路已经完整，但以下能力仍不算完全成熟：

### 6.1 消息能力仍是演示级实时

- 当前已有实时追加
- 但还没有完整 IM 能力，如：
  - 已读回执
  - 在线状态
  - 断线补偿
  - 更完整的消息类型体系

### 6.2 收藏能力已形成主链路，但历史文档口径仍有残留

- 当前前后端已有收藏接口与收藏页
- 但部分旧文档中仍保留“本地收藏为主”的历史说法

### 6.3 图片与对象存储闭环还不算完全产品化

- 当前系统已保留图片与对象存储结构
- 但完整上传与展示策略仍可继续收口

### 6.4 推荐机制已经可用，但仍是系统内实现

- 首页推荐已具备接口和结果流
- 当前不是独立推荐平台，而是系统内自实现推荐能力

## 7. 结论

截至当前版本，SwapCampus 已不再是单纯的页面集合，而是具备以下完整结构的系统：

- 有真实页面入口
- 有角色差异
- 有商品交易主链路
- 有校园服务子模块
- 有站内消息
- 有后台治理
- 有 Docker 化可复现部署
