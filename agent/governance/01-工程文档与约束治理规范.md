# 工程文档与约束治理规范

## 1. 目的

本规范用于约束 SwapCampus 当前阶段的工程文档、结构性规范和重构约束的管理方式。

目标不是服务课程归档，而是服务后续持续重构，确保：

- 结构性约束有单一事实源
- 文档和代码不会长期脱节
- 大规模重构时不会失去边界
- UI、数据、模块规范可以持续沉淀

## 2. 文档分层

当前仓库文档分为两层：

### 2.1 `docs/`

用于保留课程设计交付、过程记录、验收证明、需求与设计说明。

这些文档的主要作用是：

- 对外说明
- 课程交付
- 过程追溯
- 运行与验收留档

### 2.2 `agent/`

用于保留当前仍有效、会直接指导后续重构和实现的工程规范。

这些文档的主要作用是：

- 定义统一约束
- 收口单一事实源
- 约束结构演进方向
- 为 UI / 数据 / 模块重构提供基线

## 3. `agent/` 的适用范围

只有满足以下条件的内容，才应进入 `agent/`：

1. 它不是一次性讨论记录
2. 它会持续影响代码结构或设计决策
3. 它需要被多人或后续版本反复引用
4. 它比 `docs/` 中的课程文档更接近当前真实工程口径

适合进入 `agent/` 的内容包括：

- 分类体系规范
- 商品数据结构规范
- 认证与会话约束
- 前端视觉与样式规范
- 架构边界和模块职责规范
- 设计系统和组件约束
- API 契约基线

## 4. 当前有效的单一事实源原则

任何会影响系统结构和行为的定义，都应有单一事实源。

### 4.1 分类

- 前端：`frontend/src/constants/productCategories.ts`
- 后端：`backend/src/modules/products/product-categories.ts`
- 说明文档：`agent/domain/23-商品分类体系规范.md`

### 4.2 商品数据模型

- 数据库结构：`backend/prisma/schema.prisma`
- 前端读模型：`frontend/src/services/api.ts`
- 说明文档：`agent/data/25-商品数据结构规范.md`

### 4.3 前端视觉规则

- token：`frontend/src/styles/tokens.css`
- 共享 UI：`frontend/src/components/*`
- 说明文档：`agent/ui/24-前端视觉与样式规范.md`

### 4.4 认证与会话规则

- 前端会话缓存：`frontend/src/services/session.ts`
- 前端认证状态：`frontend/src/services/auth-state.tsx`
- 后端认证实现：`backend/src/modules/auth/*`
- 说明文档：`agent/governance/27-认证与会话约束规范.md`

## 5. 文档更新触发规则

出现以下情况时，必须同步更新 `agent/`：

1. 新增或删除主模块
2. 调整前后端目录结构
3. 变更主分类、标签语义或统一入口
4. 变更商品主结构、状态枚举、媒体结构、标签结构
5. 变更共享 UI、token、交互基础规则
6. 对“单一事实源”位置进行迁移
7. 变更认证、会话或权限边界

## 6. 变更原则

### 6.1 先改规范，再做大改

若变更会影响多个页面、多个模块或多个接口，必须先修改 `agent/` 里的规范，再开始大规模重构。

### 6.2 小改可直接落代码

若变更只影响局部实现，且不改变结构约束，可直接改代码，不必先改文档。

### 6.3 课程文档不再作为结构主源

`docs/` 中的需求、设计、用户手册、验收记录可以作为背景和证明，但不应继续作为当前结构规范的主来源。

## 7. 约束等级

为避免“什么都像规范”，`agent/` 中的内容分三级：

### 7.1 L1：冻结约束

不应随意改动，改动会影响数据或全局结构。

例如：

- 商品主分类集合
- 商品核心状态枚举
- 模块边界

### 7.2 L2：实现基线

允许演进，但需要同步改动多个实现点。

例如：

- 商品卡读模型
- 发布载荷结构
- 导航信息架构

### 7.3 L3：建议性规范

用于指导重构方向，但不要求当前代码已完全满足。

例如：

- 标签独立建模
- 图片媒体增强结构
- 状态进一步拆分

## 8. 当前阶段的治理重点

当前应优先维护以下几类 `agent/` 规范：

1. 分类体系
2. 商品数据结构
3. 认证与会话约束
4. 前端视觉与样式
5. 架构与模块职责
6. 组件与页面信息架构

## 9. 结论

从现在开始，SwapCampus 的课程文档和工程规范需要明确分离：

- `docs/` 负责记录
- `agent/` 负责约束

后续所有系统性重构，应先看 `agent/`，再落代码。
