# 前端视觉与样式规范

## 1. 目的
本规范用于约束当前版本的前端视觉收口方式。先不追求完整设计系统，优先统一几个已经明确的方向，避免页面继续出现风格漂移。

当前优先级最高的约束只有 3 条：
- 使用当前配色系统
- 少边框
- 按钮无阴影

本规范适用于：
- 新开发页面
- 正在修改的旧页面
- 共享组件和局部样式重构

## 2. 配色系统
全站颜色必须优先使用现有 token，不再新增随意的零散颜色。

统一来源：
- `frontend/src/styles/tokens.css`
- `frontend/src/theme/tokens.ts`

执行规则：
- 品牌色使用现有 `--primary`、`--primary-hover`、`--primary-deep`、`--primary-soft`、`--primary-border`
- 中性色使用现有 `--paper`、`--bg`、`--line`、`--ink`、`--muted`
- 语义状态使用现有 `--success-*`、`--info-*`、`--warning-*`、`--danger-*`
- 共享 UI 层不直接写新的品牌色 hex；确实需要局部混色时，优先基于现有 token 使用 `color-mix()`

## 3. 少边框
页面分层优先靠背景、留白、排版和轻微色差，不靠重描边堆层级。

执行规则：
- 面板、卡片、表单容器默认只允许一层轻边框
- 能不用边框时，就用背景层级区分区域
- 必须使用边框时，优先使用 `var(--line)` 或 `var(--primary-border)` 的低对比版本
- 避免出现下面这些情况：
  - 双层边框
  - 高对比描边
  - 描边和厚阴影同时出现
  - 一个区域里连续堆多个小边框盒子

建议方向：
- 输入框优先做成填充式表面，再配合 hover / focus 的轻边界反馈
- 面板优先使用暖白或中性浅底，不用厚重卡片壳

## 4. 按钮无阴影
按钮的状态变化主要通过颜色、描边和底色变化表达，不通过阴影制造“悬浮感”。

执行规则：
- 主按钮、次按钮、分段按钮默认 `box-shadow: none`
- hover / active / focus 不添加按钮阴影
- 主按钮优先使用当前品牌色纯色或轻微色阶变化，不依赖渐变和投影
- 焦点态优先使用描边、outline 或背景变化，不使用阴影

## 5. 本轮落地建议
为了先把规范落地，当前优先检查以下区域：
- 顶部导航
- 登录 / 注册表单
- 发布页表单
- 主要操作按钮

如果新页面与旧页面发生冲突，先以本规范覆盖本次改动范围，不要求一次性清理全站。
