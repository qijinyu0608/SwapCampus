# 轻量压测与容量评估方案

## 1. 目的
本方案用于课程设计答辩时说明系统的容量设计思路。当前版本未做正式集群压测，因此不虚构吞吐数字，而是给出可复现的轻量测试方法和合理容量边界。

## 2. 推荐测试对象
- `GET /api/health`
- `GET /api/products`
- `GET /api/products/dashboard`
- `GET /api/messages/conversations`
- `GET /api/admin/overview`

这些接口覆盖轻量读请求，适合作为课程设计阶段的基础容量观察点。

## 3. 推荐工具
- `ab`
- `hey`
- `wrk`

如果本机未安装，可选用 Docker 中的压测镜像，避免污染宿主环境。

## 4. 示例命令
### 4.1 商品列表接口
```bash
hey -n 200 -c 20 http://localhost:3001/api/products
```

### 4.2 统计看板接口
```bash
hey -n 200 -c 20 http://localhost:3001/api/products/dashboard
```

### 4.3 后台总览接口
```bash
hey -n 100 -c 10 http://localhost:3001/api/admin/overview
```

## 5. 课程设计阶段容量结论
- 当前单机单实例部署适合答辩演示与小规模试用
- 在未引入缓存、消息队列和多实例扩容前，建议并发目标定义为“几十级并发”
- 若超过该范围，优先瓶颈通常出现在数据库查询与同步写入链路

## 6. 扩容优先级建议
1. 为统计接口增加缓存
2. 为消息通知、审核日志和推荐任务增加消息队列
3. 为后端增加 Nginx 反向代理和多实例部署
4. 为数据库增加读写分离或索引优化

## 7. 说明原则
课程设计文档中的容量描述以“可解释、可验证、不过度夸大”为原则。当前项目没有正式压测报告，因此文档只给出保守估算和测试方法，不虚构 QPS、RT、TPS 数字。
